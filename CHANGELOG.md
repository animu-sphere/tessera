# Changelog

## Unreleased — 2026-10-05

- Added prototype focus dispatch: host-owned `FocusDispatcher` accepts logical `FocusNext`/`FocusPrevious`/`Navigate`/`Activate`/`Cancel` commands over the hit-testing snapshot. Focus requires a displayed, locally visible, enabled node whose `focusable` property is true. Traversal follows tree preorder and wraps. Directional movement picks the nearest border box wholly beyond the focused edge, preferring aligned boxes, with a preorder tie-break and no wrapping. `Activate` returns the same `ActionRequest` as a pointer click, and `Cancel` requests the nearest `cancel` binding. Refresh/dispatch recover focus beside an ineligible node and restore it by author ID across tree replacement; a command that triggers recovery is consumed. `focus` rejects stale, hidden, disabled, and non-focusable targets. Pointer eligibility moved into a shared internal header, `focusable` now lists the input stage, and the pointer-menu example repeats its actions through focus commands. The contract is in [input](docs/design/input.md#implemented-prototype-focus-dispatch); JSON v1 is unchanged.
- Added rectangular overflow clipping shared by paint and hit testing: `ResolvedStyle::overflow` (`visible`/`clip`), `intersect`, and `LayoutBox::clip`, the intersection of every clipping ancestor's padding box. Paint encloses each box's commands in its recorded clip, sharing one push/pop pair across adjacent boxes. Hit testing, inspection point targets, and replay boxes honor and compare the same rectangle. Layout consumers reject stale or non-finite clips as `layout_clip`. The Vulkan scissor now includes a pixel when its center is inside the clip, matching primitive rasterization and pixel-center pointer mapping. The Win32 menu gained a clipped list, and its smoke checks per-pixel paint/hit agreement at the clip edge and clicks on each side of it at three scales. Rules are in [layout](docs/design/layout.md#implemented-prototype-algorithm), [rendering](docs/design/rendering.md#implemented-vulkan-primitive-boundary), and [input](docs/design/input.md#implemented-rectangular-hit-testing); JSON v1 is unchanged.
- Added prototype in-process inspection: `capture_inspection` returns an owned snapshot of one tree generation that joins authored identity, hierarchy, classes/events, descriptor-ordered effective properties, resolved style, geometry, semantic entries, and projection warnings. `load_document_with_sources` adds JSON v1 node/property byte spans as tooling metadata, with explicit absence when no map is supplied and rejection of mismatched maps. `resolve_target` resolves exactly one element by author ID, semantic role/name, child path, or logical point, diagnosing missing and ambiguous targets; resolved handles invoke through semantic actions and fail as stale after reload. `Diagnostic` gained defaulted equality. The contract is in [inspection](docs/design/inspection.md#implemented-prototype-capture-and-target-resolution); JSON v1 is unchanged.
- Added a prototype in-process semantic projection: `build_semantic_tree` derives preorder `root`/`button`/`text` entries from a coherent tree/style/layout snapshot, flattens other Boxes, excludes display-none and locally hidden nodes, names entries from `labelled_by` or visible content with fallback and `missing_name` warnings, and exposes enabled/focusable state and eligible `activate` actions. `request_semantic_action` returns the same `ActionRequest` as pointer activation and rejects stale, hidden, disabled, and unsupported targets. The `text` descriptor now lists the semantics stage. The contract is in [semantics](docs/design/semantics.md#implemented-prototype-projection); JSON v1 is unchanged.
- Added prototype in-process replay: `ReplayRecording` with a distinct prototype version, declared actions, viewport, initial document/styles, and bounded pointer/resize/reload steps; `play_replay` drives the ordinary tree/layout/paint/pointer path without a renderer and returns handle-free generations (geometry and paint) and ordered action requests; `compare_replay` locates mismatches with a declared geometry tolerance. Added playback, comparison, and rejection checks. The contract is in [replay](docs/design/replay.md#implemented-prototype-playback); no serialized format is defined and JSON v1 is unchanged.
- Added optional Vulkan adjacent instancing keyed by solid/image pipeline, image handle, and physical scissor, preserving packet order with per-instance transforms/colors/borders/placeholder marks. Retained individual draws as the reference, added completion-owned uploads and submission counters, and enabled batching in the Win32 menu host. GPU fixtures compare both paths at four scales and exercise multiple submissions, rejection and partial retirement; the native smoke checks reduction and retention. Rules are in [rendering](docs/design/rendering.md#implemented-vulkan-adjacent-batching).
- Added basic property metadata: `PropertyDescriptor` entries for `disabled`, `focusable`, `labelled_by`, and `text` with stable encoded names, value type, accepted/required node kinds, non-materialized absent values, affected stages (including input targeting), and editor category. Validation, pointer `disabled` defaults, and layout/paint `text` lookup now use them, with agreement checks across node kinds, value types, absence, and JSON v1 encoding. The contract is in [UI model](docs/design/ui-model.md#implemented-property-metadata); JSON v1 is unchanged.
- Added the Win32 `tessera_vulkan_menu` example host: a JSON menu laid out, painted, and presented through a FIFO sRGB swapchain with two frames in flight and fence-based retirement; per-monitor DPI/resize update points with exact logical extents; pixel-center pointer mapping; mouse capture and `PointerCancel` on capture loss, cancel mode, focus loss, and leave; and host-executed actions. Its `--smoke` mode posts mouse/cancel/DPI messages under synchronization validation and checks actions and presented pixels. Rules are in [rendering](docs/design/rendering.md#implemented-win32-vulkan-example-host) and [input](docs/design/input.md#host-boundary).
- Added explicit Vulkan placeholder Text opt-in below `UiDrawList`: original 5x7 ASCII letter/digit marks, uppercase shapes for lowercase, space suppression and missing-scalar boxes, baseline placement, clip/transform/alpha agreement, and atomic glyph/font/geometry rejection without atlas resources. Added offscreen glyph images at four scales and a JSON -> layout -> paint -> GPU Text menu. The contract is in [rendering](docs/design/rendering.md#implemented-vulkan-placeholder-text); native Win32 presentation remains active scope.
- Added optional `tessera::vulkan` and pinned Slang SPIR-V builds below the draw-list boundary: host-borrowed device/render pass/command buffer, ordered solid/rounded/inside-border/image draws, affine transforms, intersected physical scissors, linear-light straight-alpha blending, and completion-safe bounded image descriptors. Added validation-layer offscreen GPU fixtures for pixels, fractional scales/resize, rejection, and retirement. Dependency/Win32 host choices are recorded in [dependencies](docs/reference/dependencies.md); native presentation and glyph rasterization remain active scope.
- Added rectangular `hit_test` and host-owned `PointerDispatcher`: reverse-preorder targeting, half-open border boxes, local visibility/inherited disabled rules, label-to-ancestor activation lookup, primary press/release/drag/cancel, independent pointers, snapshot refresh/replacement recovery, and rejected-input state preservation. Added the synthetic `pointer-menu` example and focused pointer fixtures. Rules and remaining native-host/focus scope are in [input](docs/design/input.md).
- Added backend-neutral `build_paint_list`: full-tree background, inside-border, and owned Text glyph commands from validated tree/styles/layout, with deterministic preorder, ancestor opacity, local visibility, input-topology checks, and located shaping failures without partial output. Extended the `flex-layout` example to emit eight paint commands, and added numeric paint/ownership/failure checks. Rules and limits are in [rendering](docs/design/rendering.md).
- Added the Phase 1 layout prototype: full-tree `compute_layout` producing `LayoutResult` from a tree, resolved styles, viewport, and `TextShaper`, with border-box fixed sizes and min/max limits, single-line row/column flex (margin, padding, gap, justify, align/stretch, grow/shrink with limit freezing), safe overflow, and display-none/hidden handling. Added numeric layout fixtures and the `flex-layout` example. Rules are recorded in [layout](docs/design/layout.md).
- Added the first Phase 0 implementation slice: C++20 `tessera::core`, owned Box/Text documents, immutable indexed tree snapshots, typed properties, action-name validation, and actionable diagnostics.
- Added deterministic JSON v1 load/save with namespaced editor metadata, UTF-8 checks, finite binary64 values, and bounded input/nesting.
- Added Phase 0 subsystem contracts: logical-unit geometry, `ResolvedStyle` and `LayoutInput`/`LayoutBox`, normalized `InputEvent` values and host `ActionRequest` lifetime rules, `UiDrawList` with balanced clip/transform validation, `FrameInfo`/`UiRenderer` submission and retirement rules, and the `TextShaper` boundary with a deterministic `PlaceholderTextShaper`.
- Added a core-only serialization example and focused document/failure/lifetime and contract validation checks. Verification configuration and limitations are recorded in the [support matrix](docs/reference/support-matrix.md).

Release records belong here; live capability status is in the [support matrix](docs/reference/support-matrix.md), and active scope is in [current work](docs/roadmap/current.md).
