# Changelog

Dated delivery history and release records. Each release is a `## vX.Y.Z — YYYY-MM-DD` section matching [VERSION](VERSION); unreleased entries collect under `## Unreleased`. Live capability status is in the [support matrix](docs/reference/support-matrix.md), and active scope is in [current work](docs/roadmap/current.md).

## Unreleased

- Added owned, versioned in-process font profiles with explicit asset bytes/versions, concrete faces, fallbacks, weighted families, and logical aliases. `ProfileFontShaper` creates a fresh sealed shaping/raster service after bounded validation, rejecting duplicate identities and missing references with located diagnostics. Real-font Replay/session inspection and atlas fixtures compare independent service creations at controlled scales. The contract is in [text](docs/design/text.md#implemented-in-process-font-profile), with [evidence](docs/reference/support-matrix.md#font-profile-evidence--2026-10-09). Serialized Replay/capture inputs remain separate scope; core and JSON v1 are unchanged.

- Added host-registered font families and named logical aliases to `FontShaper`: aliases retain stable `FontId`s, select the nearest declared weight (lower-weight ties), and build independent cluster fallback stacks while glyphs retain concrete raster face IDs. Registration rejects invalid names, missing/duplicate family entries, and identity collisions without changing existing bindings. The real Win32 menu now inherits `ui-sans` through this selection path. The contract is in [text](docs/design/text.md#implemented-family-and-logical-alias-selection), with [evidence](docs/reference/support-matrix.md#font-family-and-alias-evidence--2026-10-08). JSON v1 and dependency versions are unchanged.

- Refined `FontShaper` wrapping with a bounded menu profile: prefer spaces, hyphens, and Japanese cluster boundaries; prohibit breaks around explicit glue, before declared punctuation/small kana/prolonged sound marks, and after opening brackets (including spaces). Long words retain emergency cluster wrapping; prohibited-break groups can overflow intact. Added independent expected-line and layout/paint placement checks, preserving the native/offscreen mixed-font fixtures. The exact profile and limitations are in [text](docs/design/text.md#implemented-menu-wrapping-profile), with [evidence](docs/reference/support-matrix.md#menu-wrapping-profile-evidence--2026-10-08). No dependency, serialized field, or font-selection API changed.

- Integrated real grayscale text into the Win32 Vulkan menu behind explicit `--fonts` Latin/Japanese asset paths. The optional fonts build uses one shaper/cache for layout and paint, wraps the mixed-script Start label, and records host-owned atlas uploads before each render pass, retaining images/staging through frame completion and retirement; DPI/resize regenerates resources at the new scale. Preserved the placeholder path and added a native real-font smoke with independent original-raster pixel comparison, focus/scroll/clip/action checks, and live-image lifetime checks. The example contract is in [rendering](docs/design/rendering.md#implemented-win32-vulkan-example-host), with [native evidence](docs/reference/support-matrix.md#native-real-font-menu-evidence--2026-10-08). JSON v1 and backend contracts are unchanged.

- Added frame-local grayscale glyph atlas preparation in core: bounded shelf-packed pages with transparent gutters, owned coverage, and `DrawGlyphRun` lowering to positioned/tinted `DrawImage` commands. Hosts reserve handles and own uploads/completion/retirement; cache clearing or font replacement cannot mutate previously prepared bytes. Combined font/Vulkan fixtures now draw wrapped Latin/Japanese text, ligatures and marks through the existing image pipeline and compare completed frames with independent raster sampling at fractional scales and different atlas placements. The contract is in [rendering](docs/design/rendering.md#implemented-frame-local-glyph-atlas), evidence in [support](docs/reference/support-matrix.md#glyph-atlas-and-vulkan-image-evidence--2026-10-08). Native menu integration remains next; JSON v1 is unchanged.

- Added a backend-independent bounded LRU `GlyphCache` with immutable owned grayscale results, per-face revision invalidation, and images that remain valid after eviction or face replacement. `FontShaper` now also implements `GlyphRasterizer` over its shared HarfBuzz/FreeType face registration, with fixed unhinted outline coverage, explicit stem-darkening suppression, 26.6 physical sizes, baseline bearings, and actionable size/font/glyph diagnostics. FreeType 2.13.3 is now pinned and linked directly by the optional fonts module. Added seven independent small raster references and a wrapped Latin/Japanese paint fixture; the declared fixture profile and lifetime contract are in [text](docs/design/text.md#implemented-grayscale-raster-and-cache-contract), with evidence in [support](docs/reference/support-matrix.md#glyph-raster-and-cache-evidence--2026-10-08). Atlas upload and Vulkan real-glyph drawing remain future integration; JSON v1 is unchanged.

- Added width-constrained text shaping through `TextConstraints::max_width`: `FontShaper` wraps LTR Latin/Japanese text at shaped cluster boundaries through its fallback stack, preserving ligatures, marks, UTF-8 source offsets, and per-glyph faces; the placeholder wraps by scalar. Layout remeasures automatic heights at assigned widths, including nested columns and flex rows, and paint uses the same content width. Word/Unicode line-break and kinsoku rules remain outside this prototype. Contracts are in [text](docs/design/text.md#implemented-font-shaper) and [layout](docs/design/layout.md#implemented-prototype-algorithm); evidence is in the [support matrix](docs/reference/support-matrix.md#text-wrapping-evidence--2026-10-07). JSON v1 is unchanged.

- Added font fallback stacks to `FontShaper`: `set_fallback(font, fallbacks)` sets the ordered `FontId`s tried for clusters the requested face cannot map. After shaping a line with the requested face, each fallback face reshapes the remaining glyph-0 byte ranges with the rest of the line as context, so Latin text with a Japanese fallback shapes Katakana from Noto Sans JP. Line metrics stay those of the requested face, pens accumulate per face, and a cluster no face maps keeps the last face's glyph 0 with one `missing_glyph` warning. `Glyph::font` now names the `FontId` whose face each glyph ID indexes; `PlaceholderTextShaper` sets it to the run's font. Unknown and repeated stack entries are rejected as `unknown_font` and `duplicate_font`. The contract is in [text](docs/design/text.md#implemented-font-shaper); evidence is in the [support matrix](docs/reference/support-matrix.md#font-fallback-evidence--2026-10-06). JSON v1 is unchanged.
- Added real-font shaping: the optional `tessera::fonts` module (`TESSERA_BUILD_FONTS`, default OFF) provides `FontShaper`, a `TextShaper` that shapes host-supplied TTF/OTF/TTC faces with HarfBuzz, one face per `FontId`. It applies the fonts' kerning, ligatures, and mark positioning, reports UTF-8 byte clusters across LF-separated lines, derives half-leading line metrics from the font extents, and shapes unmapped clusters as glyph 0 with a `missing_glyph` warning; invalid font data and unknown font IDs are rejected. `validate_text_input` now holds the input checks shared by every shaper. Adopted HarfBuzz 10.2.0 (pinned at configure) and FreeType 2.13.3 through vcpkg classic mode, and committed the unmodified OFL Noto Sans 2.015 and Noto Sans JP 2.004 test fixtures with notices. No glyphs are rasterized yet. The contract is in [text](docs/design/text.md#implemented-font-shaper), the adoption record in [dependencies](docs/reference/dependencies.md#adopted-text-choices), and evidence in the [support matrix](docs/reference/support-matrix.md#font-shaper-evidence--2026-10-06). JSON v1 is unchanged.
- Added `ReplaySession`, an incremental, windowless replay fixture for in-process consumers: it opens by playing a recording, applies further steps one at a time, captures an inspection snapshot of its current generation, and records `focus`/`invoke` calls on resolved handles as author-ID or path target steps, so `recording()` replays to `output()`. Stale handles and steps rejected by validation, ordering, targets, eligibility, or failed resize/reload layout leave the session unchanged; a failure after a step changes the session closes it. `play_replay` shares the same player. The contract is in [replay](docs/design/replay.md#implemented-prototype-playback); evidence is in the [support matrix](docs/reference/support-matrix.md#replay-session-evidence--2026-10-06). JSON v1 is unchanged.
- Added fixture-identity targets and host focus policies to prototype replay: `ReplayFocus` and `ReplaySemanticAction` steps resolve an author-ID, role/name, path, or point target in the current generation with `resolve_target` and then go through `FocusDispatcher::focus` or `request_semantic_action`, so a recorded automation activation requests what a click requests. `ReplayFocusPolicy` replays the Win32 host's press-to-focus and reveal rules: focus moved by a command or focus step scrolls into view and settles a generation, while press focus never reveals. Target failures keep their resolution and eligibility codes under the step. The contract is in [replay](docs/design/replay.md#implemented-prototype-playback); evidence is in the [support matrix](docs/reference/support-matrix.md#replay-target-and-focus-policy-evidence--2026-10-05). JSON v1 is unchanged.
- Added logical commands and semantic outputs to prototype replay: `FocusNext`/`FocusPrevious`/`Navigate`/`Activate`/`Cancel` steps go through `FocusDispatcher` on the shared timestamp stream, and each settled generation refreshes focus, restoring it by author ID across reloads and recovering it from disabled or hidden nodes. `ReplayOutput::semantics` records an owned semantic projection with the focused preorder index after each generation and each command step; command actions are recorded like pointer actions, and `compare_replay` locates semantic differences. Semantic warnings are relocated per observation and returned with the output. Keys remain rejected. The contract is in [replay](docs/design/replay.md#implemented-prototype-playback); evidence is in the [support matrix](docs/reference/support-matrix.md#replay-command-and-semantic-evidence--2026-10-05).
- Added semantic focus state: `SemanticInput` takes the host's focused handle for the snapshot, and `SemanticNode::focused` marks the entry it names. `focusable` now reports focus dispatch eligibility through the shared targeting rule rather than the authored property, so a disabled entry is never focusable or focused, matching `:focus` suppression in style resolution. Focus on an eligible node without an entry produces a `focus_not_exposed` warning, and a focus handle from another tree is `stale_target` at `/focused`. `InspectionInput` passes focus to the captured semantics. The contract is in [semantics](docs/design/semantics.md#implemented-prototype-projection); evidence is in the [support matrix](docs/reference/support-matrix.md#semantic-focus-state-evidence--2026-10-05). JSON v1 is unchanged.
- Added prototype scrolling: `ResolvedStyle::overflow` gained `scroll`, which clips like `clip` and makes the box a scroll container. `LayoutInput::scroll_offsets` carries host-owned requested offsets; layout records each scroll box's `ScrollGeometry` (extent covering its children's margin boxes plus trailing padding, and the offset clamped into `[0, scroll_limit()]`) and places descendants moved back by it, so paint and hit testing share scrolled geometry and clips without a paint-side transform. Nested scroll boxes compose. `route_scroll` chains a `Scroll` delta per axis from the hit target outward through eligible scroll boxes, and `scroll_into_view` returns the minimal offsets that reveal a node; both return new offsets for the host to apply at its next update point. Layout consumers reject missing or out-of-range scroll geometry as `layout_scroll`. Inspection and replay observe scroll geometry, and replay accepts `Scroll` steps. The Win32 `tessera_vulkan_menu` list now scrolls: wheel messages become `Scroll` events, focus moved by keys or gamepad scrolls into view, and the smoke checks reveal, a partial wheel, paint/hit agreement at both clip edges of the scrolled list, and a click on the scrolled button. Rules are in [layout](docs/design/layout.md#implemented-prototype-algorithm) and [input](docs/design/input.md#implemented-scroll-routing); evidence is in the [support matrix](docs/reference/support-matrix.md#scroll-prototype-evidence--2026-10-05). JSON v1 is unchanged.
- Added a prototype style resolver: a host-built `StyleSheet` of rules whose selector is one node type, class, or author ID plus required `hover`/`active`/`focus`/`disabled` states, with `StyleDeclarations` mirroring `ResolvedStyle` fields. `resolve_styles` produces one style per node from primitive defaults, the parent's `text` and `color`, base rules then state rules in sheet order (no specificity; class-list order has no effect), and optional per-node instance overrides. Hover and active match the supplied nodes and their ancestors, focus only the focused node, and disabled is inherited and suppresses the other states. Declarations, selectors, stale state handles, override counts, and combined conflicts are diagnosed. The Win32 `tessera_vulkan_menu` host now styles its menu through this resolver, and its smoke checks the `:active` background of a held button. The contract is in [styling](docs/design/styling.md#implemented-prototype-style-resolution); evidence is in the [support matrix](docs/reference/support-matrix.md#style-resolution-prototype-evidence--2026-10-05). JSON v1 is unchanged.
- Added gamepad focus navigation to the Win32 `tessera_vulkan_menu` host. XInput samples from the first connected controller, read only while the window is in the foreground, pass through a device-independent host policy that emits the keyboard path's `Navigate`/`Activate`/`Cancel` commands: D-pad over a left stick with a hysteresis dead zone, 400 ms/120 ms repeat, A/B press edges, and input held at connection ignored. The smoke checks the policy against scripted samples with synthetic times, then drives the menu with scripted samples to the same `show-credits`/`quit-game` requests as clicks and keys. Rules are in [input](docs/design/input.md#host-boundary); evidence is in the [support matrix](docs/reference/support-matrix.md#win32-gamepad-focus-evidence--2026-10-05). No core or JSON v1 contract changed.
- Added keyboard focus to the Win32 `tessera_vulkan_menu` host: its buttons are `focusable`, and `WM_KEYDOWN` becomes `FocusNext`/`FocusPrevious` (Tab, Shift+Tab), `Navigate` (arrows, repeat from the OS auto-repeat), `Activate` (Enter, Space, once per press), and `Cancel` (Escape), never also a `KeyDown`. A primary press focuses the pressed button, the focus dispatcher refreshes with the pointer dispatcher at update points, and the focused button's border color shows focus. The smoke now drives the menu with posted keys after the mouse steps and checks that keyboard activation produces the same `start-game`/`quit-game` requests as clicks. Rules are in [input](docs/design/input.md#host-boundary); evidence is in the [support matrix](docs/reference/support-matrix.md#win32-keyboard-focus-evidence--2026-10-05). No core or JSON v1 contract changed.

## v0.1.0 — 2026-10-05

Minimal Vulkan menu milestone: a JSON v1 document is laid out, painted, and presented as a pointer-operated Win32 Vulkan menu. This is a repository milestone record; no package, installation/export, or binary is distributed. The release is the `v0.1.0` tag; its fresh-build verification is in the [support matrix](docs/reference/support-matrix.md#v010-release-verification--2026-10-05).

Exit criteria accepted against support evidence:

- Deterministic geometry/paint from JSON and a visible Vulkan menu: [layout](docs/reference/support-matrix.md#layout-prototype-evidence--2026-10-05), [paint](docs/reference/support-matrix.md#paint-and-pointer-evidence--2026-10-05), and [Win32 host](docs/reference/support-matrix.md#win32-vulkan-menu-host-evidence--2026-10-05) evidence.
- Overlap, border, clip, transform, and alpha images within 2/255: [primitive](docs/reference/support-matrix.md#vulkan-primitive-evidence--2026-10-05), [batching](docs/reference/support-matrix.md#vulkan-adjacent-batching-evidence--2026-10-05), and [overflow clip](docs/reference/support-matrix.md#overflow-clip-evidence--2026-10-05) evidence.
- Native clicks produce expected action requests, and capture loss/cancel mode cancel presses: [Win32 host](docs/reference/support-matrix.md#win32-vulkan-menu-host-evidence--2026-10-05) smoke and the [interactive session](docs/reference/support-matrix.md#win32-interactive-session-evidence--2026-10-05).
- Logical/physical conversion at scales 1, 1.25, 1.5, 1.75, 2, and 2.25 with backend-neutral core types, confirmed by core-only builds that discover no Vulkan/Slang.
- Property metadata agreeing with validation and defaults: [property metadata](docs/reference/support-matrix.md#property-metadata-evidence--2026-10-05) evidence.
- Submission and resource retirement on the concrete host, with OS/compiler/GPU, placeholders, and unsupported cases recorded in support.

Not included: native transform agreement, because the menu paints and hit-tests no transforms; real fonts (Text uses explicit placeholder marks); keyboard/gamepad host input; Release-configuration evidence for the Vulkan backend and host; non-Windows or other-GPU evidence. Later scope is in [current work](docs/roadmap/current.md).

- Prepared the release: Tessera is licensed under Apache-2.0. [VERSION](VERSION) is the single version source, read by CMake as the project version. A tag-triggered [release workflow](.github/workflows/release.yml) checks the tag against `VERSION` and the changelog with `cmake/release.cmake`, builds and tests the core in Debug and Release on a hosted Windows runner, and publishes a source-only pre-release with this section as its notes. Added a security policy, code of conduct, and issue/pull-request templates, and documented the procedure in the [development guide](docs/guides/development.md#release-workflow). Source consumption by a downstream CMake project is now v0.3.0 candidate scope; installed packages remain v0.5.0 scope.

No source changed. Configuration and limits are in the [support matrix](docs/reference/support-matrix.md#win32-interactive-session-evidence--2026-10-05).
- Added prototype focus dispatch: host-owned `FocusDispatcher` accepts logical `FocusNext`/`FocusPrevious`/`Navigate`/`Activate`/`Cancel` commands over the hit-testing snapshot. Focus requires a displayed, locally visible, enabled node whose `focusable` property is true. Traversal follows tree preorder and wraps. Directional movement picks the nearest border box wholly beyond the focused edge, preferring aligned boxes, with a preorder tie-break and no wrapping. `Activate` returns the same `ActionRequest` as a pointer click, and `Cancel` requests the nearest `cancel` binding. Refresh/dispatch recover focus beside an ineligible node and restore it by author ID across tree replacement; a command that triggers recovery is consumed. `focus` rejects stale, hidden, disabled, and non-focusable targets. Pointer eligibility moved into a shared internal header, `focusable` now lists the input stage, and the pointer-menu example repeats its actions through focus commands. The contract is in [input](docs/design/input.md#implemented-prototype-focus-dispatch); JSON v1 is unchanged.
- Added rectangular overflow clipping shared by paint and hit testing: `ResolvedStyle::overflow` (`visible`/`clip`), `intersect`, and `LayoutBox::clip`, the intersection of every clipping ancestor's padding box. Paint encloses each box's commands in its recorded clip, sharing one push/pop pair across adjacent boxes. Hit testing, inspection point targets, and replay boxes honor and compare the same rectangle. Layout consumers reject stale or non-finite clips as `layout_clip`. The Vulkan scissor now includes a pixel when its center is inside the clip, matching primitive rasterization and pixel-center pointer mapping. The Win32 menu gained a clipped list, and its smoke checks per-pixel paint/hit agreement at the clip edge and clicks on each side of it at three scales. Rules are in [layout](docs/design/layout.md#implemented-prototype-algorithm), [rendering](docs/design/rendering.md#implemented-vulkan-primitive-boundary), and [input](docs/design/input.md#implemented-rectangular-hit-testing); JSON v1 is unchanged.

The contract is in [inspection](docs/design/inspection.md#implemented-prototype-capture-and-target-resolution); JSON v1 is unchanged.
