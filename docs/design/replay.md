# Deterministic UI replay

## Proposed recording contract

Replay reproduces a session through the ordinary runtime and injected host services. This is a versioned format/tool proposal: [prototype playback](#implemented-prototype-playback) and [Replay JSON v1](#implemented-replay-json-v1) implement the subsets described below, and no replay CLI exists. Capability status is in [support](../reference/support-matrix.md).

A recording identifies:

- Document format/version and initial document or fixture reference, with explicit update/reload events.
- Logical viewport, device scale, and viewport/scale changes.
- Theme/style inputs and their revisions.
- Locale, font/fallback configuration, initial host-declared test state and its schema, and random seed when the host uses randomness.
- Ordered normalized input stream.
- Host time stream, including frame/update boundaries and animation-clock values.
- Resource readiness, failure, and replacement transitions, plus fixture font/asset identities.

Use fixture-owned resources and explicit readiness timing instead of relying on live filesystem/network completion. Define schema versioning, unsupported-version diagnostics, bounds, and deterministic event ordering before freezing the format. Document, replay, and semantic schema versions are distinct.

## Implemented prototype playback

[replay.hpp](../../include/tessera/replay/replay.hpp) implements an in-process subset of this contract. It is not a stable API and does not extend UI JSON v1; [Replay JSON v1](#implemented-replay-json-v1) serializes its recordings.

- **Recording.** `ReplayRecording` holds a replay version (only `replay_version` 1 is accepted), the host's declared actions as a `ValidationContext`, a declared `ReplayEnvironment`, the logical viewport, an initial `UiDocument` with one `ResolvedStyle` per node in tree preorder, and at most `max_replay_steps` (10000) ordered steps. A step is a normalized `InputEvent`, a `ReplayResize` with a new logical viewport, a `ReplayReload` with a replacement document and its styles, a `ReplayFocus` (host programmatic focus), or a `ReplaySemanticAction` (a semantic invocation with a binding, `activate` by default, as from an accessibility or automation client). Focus and semantic action steps name their node by an [inspection target](inspection.md#implemented-prototype-capture-and-target-resolution) (author ID, semantic role and name, child path, or logical point) rather than a handle, and carry no timestamp. A `ReplayFocusPolicy` enables, separately and off by default, the [Win32 host's](input.md#host-boundary) press policy (`press_focus`) and reveal policy (`reveal_focus`). Input steps are pointer events, `Scroll`, or the logical commands `FocusNext`, `FocusPrevious`, `Navigate`, `Activate`, and `Cancel`; keys are translated by the host before recording, as for the dispatcher. Styles are supplied already resolved; recordings carry no stylesheet or interaction state for the [prototype resolver](styling.md#implemented-prototype-style-resolution). Time apart from input timestamps, scale changes, resources other than a font profile, and host state are not recorded; the caller injects the `TextShaper`.
- **Environment.** `ReplayEnvironment` declares host configuration that logical playback does not interpret: device `scale` (pixels per logical unit, 1 by default), `locale` (`und` by default), and the `ReplayText` service the host must inject. The scale must be finite and positive (`invalid_number` or `out_of_range` at `/environment/scale`). The locale is hyphen-separated subtags of 1–8 ASCII letters or digits whose first subtag has 2–8 letters, at most 64 bytes, compared exactly without canonicalization (`invalid_locale` at `/environment/locale`). Text is `placeholder` (the `PlaceholderTextShaper`, with empty `id` and `sha256`, else `invalid_text_service` at `/environment/text`) or `font_profile` with a host fixture `id` of 1–256 UTF-8 bytes without ASCII controls (`invalid_identifier` or `invalid_utf8` at `/environment/text/id`) and the profile's identity as 64 lowercase hex digits (`invalid_digest` at `/environment/text/sha256`). Version 1 declares no animation clock and no readiness transitions: input timestamps are the only time, and every declared resource is ready before the initial snapshot. `play_replay` and `ReplaySession::open` reject an invalid environment before playing; playback does not inspect the injected shaper against the declaration.
- **Playback.** `play_replay(recording, shaper)` runs the ordinary `UiTree::create`, [`compute_layout`](layout.md#implemented-prototype-algorithm), [`build_paint_list`](rendering.md#implemented-paint-generation), [`PointerDispatcher`](input.md#implemented-pointer-dispatch), [`FocusDispatcher`](input.md#implemented-prototype-focus-dispatch), and [`build_semantic_tree`](semantics.md#implemented-prototype-projection) path without a renderer. The initial snapshot and each resize/reload/scroll step settle a full-tree generation and then `refresh` pointers and focus; a reload creates a new tree identity, so a held press is cleared and focus is restored by author ID as for any snapshot replacement, and focus on a node that became disabled or hidden moves by the dispatcher's recovery rule. A command step goes through focus dispatch against the current snapshot without settling a generation. A focus or semantic action step captures the current generation, resolves its target with `resolve_target`, and then calls `FocusDispatcher::focus` or [`request_semantic_action`](semantics.md#implemented-prototype-projection), so their eligibility rules apply; neither depends on whether the node is clipped or scrolled out of view. Pointer steps move focus only under `press_focus`: a primary `PointerDown` whose dispatch records a press owner other than the focused node focuses that owner, and leaves focus unchanged when the owner is not focusable. Under `reveal_focus`, a command or focus step that moves focus to a different node, including a consumed command that recovers focus, applies [`scroll_into_view`](input.md#implemented-scroll-routing) for it; when an offset changes, the step settles a new generation as a scroll step does. Press focus never reveals. All input steps share one non-decreasing timestamp stream (`event_order` at `/steps/<index>/timestamp`). A scroll step goes through [scroll routing](input.md#implemented-scroll-routing) against the current snapshot; playback stores the returned offsets as layout's requested offsets, which a reload resets to zero and a resize keeps for layout to re-clamp. `KeyDown`, `KeyUp`, and `TextInput` are rejected as `unsupported_event` at `/steps/<index>/event`.
- **Outputs.** `ReplayOutput` owns, per generation, the producing step (absent for the initial snapshot), every layout box as preorder node index, parent index, border box, border/padding edges, visibility, optional clip, and optional scroll geometry, and the owned paint list. Semantic observations are recorded after each generation settles, after each command or focus step that settles no generation, and after a pointer step that moves focus, in that order: each `ReplaySemantics` holds the observing step, its generation, the focused node's preorder index (present even when the node has no entry), and the projected entries with preorder node and `labelled_by` indices in place of handles. Action requests from pointer, command, and semantic action steps are recorded in order with their input step, generation, binding, action name, binding-owner preorder index, and author ID when present. No `NodeHandle` or tree identity escapes, so repeated playback compares equal.
- **Failures.** An unsupported version is `unsupported_version` at `/version`; too many steps is `out_of_range` at `/steps`; environment diagnostics are listed above. Other diagnostics come from the reused stage and are relocated under their source: document diagnostics under `/document` or `/steps/<index>/document`, layout/paint/dispatch diagnostics under the root for the initial snapshot or `/steps/<index>` for a step (for example `/steps/2/timestamp` or `/steps/0/viewport/width`). Target failures keep their resolution or eligibility code under the step: `target_not_found` or `ambiguous_target` at `/steps/<index>/target` (or `/target/children/<n>`), `not_focusable` or `disabled_target` at `/steps/<index>/target`, and `unsupported_action` at `/steps/<index>/binding`. Failure returns no partial output. Semantic warnings such as `missing_name` and `focus_not_exposed` are relocated the same way per observation (for example `/nodes/1` initially and `/steps/0/nodes/1` after a command) and returned with a successful output.
- **Session.** `ReplaySession::open(recording, shaper)` plays a recording as `play_replay` does, failing the same way, and then accepts further steps one at a time with `apply`, located at `/steps/<n>` for the *n*th accepted step and returning that index with the step's semantic warnings. `capture` returns an [inspection snapshot](inspection.md#implemented-prototype-capture-and-target-resolution) of the current generation with the current focus, so an in-process consumer resolves a target and passes the handle to `focus` or `invoke` (a binding, `activate` by default). These record a focus or semantic action step that names the node by author ID, else by child-index path; a handle from a replaced tree is `stale_target` at `/steps/<n>/target`. `recording()` holds only accepted steps and `output()` the observations so far, so playing the recording reproduces the output. A step rejected by validation, timestamp order, target resolution, eligibility, or a reload/resize whose layout or paint fails leaves the session unchanged and unrecorded, including its tree, viewport, offsets, clock, and focus. A failure after a step has changed the session closes it; later calls fail as `closed_session`. A moved-from session must not be used.
- **Comparison.** `compare_replay(expected, actual, geometry_tolerance)` reports one `replay_mismatch` per difference, located in the expected output: counts at `/generations`, `/generations/<g>/boxes`, `/generations/<g>/paint/commands`, `/semantics`, `/semantics/<s>/nodes`, and `/actions`; fields such as `/generations/<g>/boxes/<b>/border_box` and `/semantics/<s>/focused`; and whole commands, semantic entries, and actions at their index. Box rectangles, clips, edges, and scroll extents/offsets match within the non-negative finite tolerance in logical units (inclusive); clip and scroll presence, node/parent indices, visibility, steps, paint commands, semantic observations, and actions must be equal. An invalid tolerance is reported at `/geometry_tolerance`.

For controlled real text, a recording declares an [in-process font profile](text.md#implemented-in-process-font-profile) by digest; the host supplies the profile, for example restored from [font profile JSON v1](text.md#implemented-font-profile-json-v1), and passes its sealed `ProfileFontShaper` as the ordinary injected shaper and rasterizer. [replay_fonts.hpp](../../modules/fonts/include/tessera/fonts/replay_fonts.hpp) in the optional fonts module computes that identity and checks a supplied profile against it:

- `font_profile_sha256(profile)` is the lowercase hex SHA-256 of the profile's canonical `save_font_profile` output, final LF included, and fails as saving fails. It identifies exact ordered declarations and asset bytes; reordered equivalent registrations have different digests.
- `verify_replay_fonts(recording, profile)` returns `font_profile_mismatch` at `/environment/text/kind` for a placeholder declaration and at `/environment/text/sha256` for a different digest, or the profile's save diagnostics. The declared `id` is a host lookup name and is not compared.

The core recording neither embeds nor resolves the profile, and core playback does not call the check. The host retains both inputs and keeps the service alive while a session borrows it.

Fixture identities are document-scoped author IDs and exact role/name matches; component scopes and keys do not exist yet. Pointer steps still carry positions rather than targets. Resource readiness transitions, resources other than a font profile, animation time, and scale changes remain proposals above.

## Implemented Replay JSON v1

[replay_serialization.hpp](../../include/tessera/replay/replay_serialization.hpp) defines `load_replay` and `save_replay` in core. The format serializes a whole `ReplayRecording`; its `version` is the replay version, independent of UI JSON, semantic, and font profile versions. Documents are embedded [UI JSON v1](../../formats/tessera-ui/README.md) objects under its rules. A font profile is identified by digest, never embedded. The format carries no paths, resource lookup, output observations, or host state.

All fields below are required. Objects reject unknown and duplicate fields; null, coercion, omitted defaults, and extensions outside embedded documents are rejected. Field names match the in-process diagnostic paths, so a playback diagnostic such as `/steps/2/timestamp` or `/steps/0/viewport/width` is a JSON pointer into the encoded recording.

| Object | Fields and values |
| --- | --- |
| Root | `version`: 1; `actions`: host action names; `policy`; `environment`; `viewport`: size; `document`: UI JSON v1 document; `styles`: preorder style array; `steps`: ordered step array |
| Policy | `press_focus`, `reveal_focus`: booleans |
| Environment | `scale`: number; `locale`: string; `text`: `{"kind":"placeholder"}` or `{"kind":"font_profile","id":…,"sha256":…}` |
| Size / point | `width`, `height` / `x`, `y`: numbers |
| Style | Every `ResolvedStyle` field by name. Enumerations are lowercase strings (`flex`/`none`, `column`/`row`, `start`/`center`/`end`/`space_between`, `start`/`center`/`end`/`stretch`, `visible`/`clip`/`scroll`, `visible`/`hidden`); `width`/`height` are a number or `"auto"`; `max_width`/`max_height` are a number or `"none"` (unbounded); edges are `top`, `right`, `bottom`, `left`; colors are `r`, `g`, `b`, `a`; `text` is `font`, `size`, `line_height` (number or `"normal"`), `weight` |
| Input step | `type`, `timestamp` (integer microseconds within ±(2^53−1)), and by type: `pointer_move` `pointer`, `position`, `modifiers`; `pointer_down`/`pointer_up` also `button` (`primary`/`secondary`/`middle`); `pointer_cancel` `pointer`; `scroll` `position`, `delta`, `modifiers`; `navigate` `direction` (`up`/`down`/`left`/`right`), `repeat`; `focus_next`, `focus_previous`, `activate`, `cancel` nothing else |
| Modifiers | `shift`, `control`, `alt`, `super`: booleans |
| Other step | `resize`: `viewport`; `reload`: `document`, `styles`; `focus`: `target`; `semantic_action`: `target`, `binding` |
| Target | `{"kind":"id","id":…}`, `{"kind":"semantic","role":…,"name":…}` (`root`/`button`/`text`), `{"kind":"path","children":[…]}`, or `{"kind":"point","position":…}` |

Numbers are converted to the in-process binary32 fields; a value beyond the finite binary32 range is `out_of_range`. Pointer IDs, font IDs, and path indices are unsigned 32-bit integers, and `weight` is an unsigned 16-bit integer before style validation. `key_down`, `key_up`, and `text_input` types are `unsupported_event` at `/steps/<i>/type`; another type or target kind is `unknown_value`.

Saving uses lexically sorted object keys, preserved array order, compact JSON, the shared binary64 JSON number formatter (exponent notation for large integers), and one final LF. Each binary32 value saves as its shortest decimal spelling when that reads back to the same value through binary64, else as its exact value, so load restores every field exactly. Actions save in sorted order; loading rejects a repeated action as `duplicate_action`. Equal recordings serialize identically, and saving a loaded recording reproduces its canonical bytes.

Load and save check every value that needs no shaper or snapshot and return no partial value: the version, step bound, and environment as for playback; action names (`invalid_identifier` at `/actions/<i>`, in sorted order when saving); documents against the declared actions, located under `/document` or `/steps/<i>/document`; style values at `/styles/<j>` or `/steps/<i>/styles/<j>`, at most 10000 per array; viewports; input events at playback's paths, plus `unsupported_event` at `/steps/<i>/event` and `out_of_range` for timestamps beyond the exact JSON range when saving; and target coordinates, roles, and UTF-8. Value diagnostics keep in-process field paths, for example `/styles/0/width/value`, whose byte offset is that of the nearest encoded value. Timestamp order, style counts, target resolution, eligibility, layout, and paint remain playback checks. Source/output is bounded to `max_serialized_replay_bytes` (64 MiB), JSON values to `max_replay_json_values` (4 Mi), and nesting to 256; embedded documents keep their node limits, not UI JSON's 4 MiB file bound.

Load errors carry JSON pointers and UTF-8 byte offsets; schema errors use `missing_field`, `unknown_field`, `schema_type`, or `unknown_value`, and parser limits keep the shared `size_limit`, `json_value_limit`, `depth_limit`, `duplicate_member`, and syntax codes. Save errors have no source offset.

## Playback and outputs

Playback injects recorded inputs at the [defined update points](architecture.md#frame-scheduling), using the same runtime as application and editor preview. It observes:

- Layout geometry.
- [Semantic projection](semantics.md).
- Ordered application-facing [action requests](input.md#event-to-action-boundary).
- Backend-neutral paint command sequence.
- Optional GPU screenshots under declared backend/device tolerances.

Expect exact values where the numeric contract permits them; otherwise declare geometry tolerances. Compare command semantics and owned data rather than pointer addresses, cache allocation order, or process-specific handles. Resolve recorded targets through fixture identities with defined ambiguity/missing-target diagnostics.

GPU images are optional adapter evidence with target size, scale, color format, fonts, device and tolerance metadata. An image hash alone is not portable cross-driver equivalence. Core replay must remain runnable without a renderer; the [offscreen runner](inspection.md#implemented-prototype-offscreen-runner) plays a recording first and then captures each generation through a declared host adapter.

[Inspection snapshot bundles](inspection.md#proposed-runner-and-snapshot-bundle) package observations at a selected generation; they do not replace the ordered recording. State restore uses the declared host adapter. Animation may be disabled or advanced at explicit fixture times, never read from an uncontrolled wall clock. Bundle exports and performance durations are separate from deterministic playback assertions.

## Tooling boundary

Recording and playback tooling may support regression tests, bug reports, navigation checks, CI, and Path-finder previews. A future CLI spelling is an open decision; do not document a runnable command until a tool exists.

Host clocks, resources, input normalization, and GPU scheduling remain host responsibilities. Replay supplies controlled adapters to those boundaries, rather than adding a second runtime or hidden global clock.

## Verification

The [testing guide](../guides/testing.md#replay-fixtures) owns test procedure. [Replay checks](../../tests/replay/replay_tests.cpp) cover prototype playback of clicks, drag-out, resize, and reload with a held press, and of a scroll step followed by a click on the moved button; command steps that request the same actions as clicks, with per-step semantic focus, focus restored across a reload by author ID, and recovery from a disabled focused button; reveal of command- and ID-targeted focus in a scrolled menu with and without the policy; semantic action steps that equal a click on a button scrolled out of view; press focus that does not reveal and skips a non-focusable press owner; missing, ambiguous, out-of-range path, non-focusable, disabled, and unexposed-binding targets; sessions whose stepwise output equals whole-recording playback, whose consumer handles are recorded by author ID or path and replay equal, and which reject stale handles, missing targets, backward time, invalid viewports, and invalid reloads without changing; observed geometry/paint/semantic/action identities and located semantic warnings; repeated-run equality; located comparison mismatches and tolerance; and rejected versions, environments, bounds, documents, styles, viewports, key input, scroll deltas, and timestamp order across pointer, scroll, and command steps. [Serialization checks](../../tests/replay/replay_serialization_tests.cpp) round-trip every step type, target form, enumeration, style keyword, environment, and exact binary32 value with byte-stable re-encoding; restore playable and session-produced recordings to equal outputs; reject malformed schemas, values, embedded documents, key steps, and parser/step bounds with located offsets, and invalid recordings on save; and check the SHA-256 helper against FIPS vectors. [Profile fixtures](../../tests/text/font_profile_tests.cpp) restore a Replay JSON recording and font profile JSON to equal mixed-font playback and atlas outputs at the declared scale and reject mismatched or placeholder declarations. Scale changes and resource readiness ordering still need fixtures. Compare future incremental updates with full-tree playback. Publish supported configurations and actual results only in support.
