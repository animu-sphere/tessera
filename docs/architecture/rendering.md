# Rendering

## Core invariants

- Backends consume backend-neutral resolved draw data; they do not query layout, signals, components or application state.
- Submission borrows a coherent snapshot and retains referenced resources until declared completion-safe retirement.
- Paint order, blend/clip/transform boundaries and logical-to-physical conversion are explicit. Optimized paths preserve reference output under declared tolerances.

## Implemented draw-list contract

[draw_list.hpp](../../include/tessera/render/draw_list.hpp) defines `UiDrawList`, an owned ordered vector of commands. Later commands paint above earlier ones. Geometry is in logical units within the current transform.

| Command | Meaning |
| --- | --- |
| `DrawRect` | Solid or optional multi-stop linear/radial-gradient fill, rectangle/rounded rectangle or ellipse, with opt-in 4x4 pixel coverage |
| `DrawBorder` | Border painted inside its rectangle with per-edge widths |
| `DrawStroke` | Uniform solid/dashed inside stroke, square or rounded, with opt-in 4x4 pixel coverage |
| `DrawShadow` | Finite distance-based outer falloff before the fill, or inset falloff clipped inside the rounded box after the fill |
| `DrawImage` | `ImageHandle`, normalized source rectangle, and tint |
| `DrawGlyphRun` | Owned [`GlyphRun`](text.md) placed at the text box top left, with color |
| `PushClip` / `PopClip` | Intersect / restore the axis-aligned clip |
| `PushTransform` / `PopTransform` | Compose `current * transform` / restore; `Affine2D` maps `x' = a*x + c*y + tx`, `y' = b*x + d*y + ty` |

Colors are sRGB-encoded with straight alpha in [0, 1]; backends convert to their target format and blending convention. A node's opacity is multiplied into its command colors; group opacity (offscreen composition) is not representable. `ImageHandle` is a neutral, nonzero value issued by the host/backend resource system; the draw list never contains GPU objects.

Clips and transforms share one LIFO stack with a maximum depth of 64. `validate(UiDrawList)` reports a pop that does not close the innermost push of the same kind or a push left open (`unbalanced_stack`), excessive nesting (`stack_limit`), a clip pushed while the composed transform rotates or skews (`unsupported_clip`), a non-invertible transform (`singular_transform`), a zero image handle (`invalid_handle`), and non-finite or out-of-range geometry and colors. Paths are `/commands/<index>/...`.

### Implemented analytic fills

[`FillShape`](../../include/tessera/style/fill_shape.hpp) selects `rectangle` (default) or `ellipse` in `DrawRect::shape` and `ResolvedStyle::background_shape`. `DrawRect::antialias` and `ResolvedStyle::background_antialias` default to false. Both style fields are paint-only, noninherited and accept exact typed theme tokens; explicit `rectangle`/`false` declarations restore the defaults. Shape changes only the solid or gradient background, not borders, outlines, shadows, descendant clips, layout, scrolling or rectangular input geometry. Use a borderless box for a circular status mark; an ellipse background does not implicitly turn a box border into an ellipse stroke.

Geometry stays in the untransformed logical border box. Rectangle coverage uses the existing rounded-box distance test with radius clamped to half the smaller side. An ellipse occupies the whole box and tests `length(2 * p / size - 1) <= 1`; equal box dimensions produce a circle. This normalized ellipse equation is an inside/outside function, not an exact Euclidean signed distance. Ellipse coverage ignores `corner_radius`, while ordinary finite/nonnegative radius validation still applies. Empty boxes paint nothing.

With antialiasing enabled, CPU and Vulkan reference/batch evaluate the same fixed 4x4 physical-pixel sample grid as strokes, offsets `{-3/8, -1/8, 1/8, 3/8}` per axis. Samples transform directly back into local coordinates; local box edges are half-open `[0, size)`. Coverage is covered samples / 16. Expanded raster bounds retain a half-pixel fringe on every physical edge, including transformed/mirrored boxes. Ancestor clips retain their whole-pixel center rule and do not restart shape or gradient coordinates. This is bounded analytic supersampling, not exact area integration, derivative-based SDF smoothing, hardware MSAA or Gaussian blur; sub-grid shapes may disappear.

Solid colors and gradients retain their existing linear-light source-over contract. The fill is evaluated at the physical pixel center, even for partially covered edge pixels, then coverage attenuates its premultiplied RGB and alpha exactly once. Gradient stops and interpolation are unchanged. Hard rectangle fills retain their legacy raster behavior; hard ellipses sample at the reconstructed physical pixel center on Vulkan to avoid raster-quantized interpolation shifting the curve.

The 112-byte Vulkan primitive ABI is unchanged: the previously unused fourth `transform1` component carries ellipse/smooth flags. No new buffer, texture or pass is needed; gradients and batches keep normal completion-safe retirement. Unknown shape enums reject as `unknown_value` at `shape` or `background_shape`. Vulkan rejects subnormal positive ellipse dimensions, nonnormal reconstructed-transform determinants/scale reciprocals, or unrepresentable coverage bounds, normalized fringe coordinates and gradient projections as `geometry_overflow` before recording or changing frame/upload state. There is no rectangle or hard-edge fallback. CPU uses scalar double arithmetic without those binary32 precision limits.

Replay v1/v2 resolved styles encode `background_shape: "ellipse"` and `background_antialias: true` only when nondefault; absence or explicit `"rectangle"`/`false` selects the defaults and preserves legacy canonical bytes. Unknown shape strings reject as `unknown_value`; a nonboolean antialias flag rejects as `schema_type`. Initial and reloaded styles use the same encoding.

Owner checks cover noninheritance, typed tokens and explicit default replacement, located validation, owned paint/opacity and unchanged layout/borders, exact circle/half/quarter-pixel coverage, clamped radii, empty boxes, transparent gradients, clipping and independent four-scale ellipse equations. Vulkan reference/batch/repeat compares circle/ellipse and rounded fills, sample-grid edges, gradients, mirror/skew/rotation and rejection/retirement with CPU at scales 1, 1.25, 1.5 and 2 within the unchanged 2/255 linear-channel tolerance. The [Inspector](../guides/inspector-hierarchy.md#analytic-backgrounds) uses a circular Enabled indicator and smooth radial card.

### Implemented procedural fills

[`ProceduralFill`](../../include/tessera/style/procedural_fill.hpp) requests a backend-registered shader inside an ordinary background fill: `DrawRect::procedural` and the paint-only, noninherited `ResolvedStyle::background_procedural`. It carries a logical `shader` identity (1-128 printable ASCII bytes without spaces), at most 16 typed `ProceduralValue` parameters (`float`, `Point` or `Color`), a `time` in seconds, an `opacity` in [0, 1] and a finite `time_rate` (default 0). Draw lists carry no source, compiler, SPIR-V or GPU object.

Tessera reads no clock. In a style, `time` is the phase at host time 0 and `time_rate` the shader seconds per host second; 0 is a static fill and negative rates run backwards. `PaintInput::host_time` is a finite host time in seconds (default 0) whose origin, pausing and scheduling the host owns. For a nonzero rate, paint evaluates `time + time_rate * host_time` in double and rounds it once into the command's `time`; a result beyond finite float range rejects paint as `time_overflow` at `/nodes/<i>/background_procedural/time` without a partial list, and a nonfinite host time rejects as `invalid_number` at `/host_time`. Static fills ignore host time. Changing host time is a paint-only update: styles, layout, geometry, fallback and input are unchanged. Backends draw the command's `time` and never read `time_rate`; it remains in the command so `time_dependent(const UiDrawList&)` can report that a list moves and its host should request further frames while showing it. That reports the request, not execution: a backend drawing the static fallback presents identical frames. Float shader time keeps sub-millisecond steps only up to 8192 s (about 2.3 hours) of host time at rate 1, and steps by about 8 ms after a day; a fill that needs precision over longer runs wraps its own periodic phase from parameters, or the host restarts its clock origin.

The procedural fill replaces color/gradient only where a backend executes the named shader. Otherwise the same command's `color` or `gradient` is the declared fallback, drawn exactly as without the request; a transparent fallback omits the fill. Paint derives that fallback from `background`/`background_gradient`, fades it and multiplies `ProceduralFill::opacity` by inherited opacity, and emits the fill when either is visible. Shape, corner radius, opt-in 4x4 coverage, clips, transforms and paint order are those of [analytic fills](#implemented-analytic-fills); borders, shadows, outlines, layout and rectangular input are unchanged.

Profile `fill-v1` is one background fill, one pass, typed uniforms and no image, sampler or storage access. [procedural.slang](../../backends/vulkan/shaders/procedural.slang) defines the Slang ABI: a fill implements `IProceduralFill::shade(ProceduralInput)` and expands `TESSERA_PROCEDURAL_FILL` once to define fragment `proceduralMain`. `ProceduralInput` supplies the pixel-center `position` in untransformed local logical units within `[0, size)`, `size`, `deviceScale`, `time` and `parameter(i)`. Each parameter occupies one float4 slot: numbers `(v, 0, 0, 0)`, points `(x, y, 0, 0)` and colors as linear-light RGB with straight alpha; out-of-range slots read zero. The shader returns linear-light straight-alpha color, clamped to [0, 1]; coverage and opacity scale alpha once before the ordinary source-over blend.

`tessera_add_procedural_fill(<target> <source> <output>)` in the [Vulkan module build](../../backends/vulkan/CMakeLists.txt) compiles one fill at build time with the pinned `slangc` to a SPIR-V 1.3 fragment artifact. There is no runtime Slang compiler. `VulkanRenderer::register_procedural_fill` borrows the words and declared parameter kinds, checks the identity, kind enums and bound, SPIR-V magic, fragment `proceduralMain` entry and the absence of image/sampler types, then creates reference and (when enabled) batch pipelines sharing the primitive vertex stages and layout. Failures return `invalid_identifier`, `procedural_parameter_limit`, `unknown_value`, `invalid_shader`, `procedural_abi` or `procedural_fill_limit` (64 fills) without registering anything; Vulkan pipeline creation failures throw like other creation failures. These checks are an ABI gate, not a sandbox: the host trusts the artifact's code and work bounds.

At submission an unregistered identity draws the fallback and counts in `VulkanSubmissionStats::procedural_fallbacks`; a registered one counts in `procedural_fills`. A parameter count or kind that differs from the registration rejects as `procedural_parameter_mismatch` at `/commands/<i>/procedural/parameters[/<j>]` before recording, consuming no frame or upload. Parameters share the frame's gradient-stop storage buffer, two slots per 32-byte record, under the same device range and exact-index bound (`fill_data_limit`). Packets keep mode 12 in the unchanged 112-byte primitive ABI; adjacent packets merge only with the same procedural pipeline and scissor. A fill referenced by an unretired frame cannot be replaced or unregistered (`resource_in_use`); `unregister_procedural_fill` of an unknown identity returns `unknown_shader`.

The scalar CPU reference executes no shaders: it draws every request's declared fallback and reports the count through `CpuRenderer::procedural_fallbacks()` for the last successful submission. That is a substitute, not CPU validation of the shader. Replay v1/v2 resolved styles encode `background_procedural` with `shader`, typed `parameters` (`{"number":…}`, `{"point":…}` or `{"color":…}`), `time`, `opacity` and a nonzero `time_rate`, omitted when absent. Replay records no host time; recorded playback paints at host time 0.

Owner checks cover located validation, noninheritance and explicit clearing, paint opacity/fallback derivation, host-time evaluation, overflow and `time_dependent`, CPU fallback pixels/counts and Replay round trips. The Vulkan fixture registers build-time fills on both paths: a constant fill must match solid `DrawRect` pixels within 1/255 for hard/rounded/ellipse/smooth, clipped/rotated and opacity-scaled fills at scales 1, 1.25, 1.5 and 2; a probe fill checks position, size, time and typed parameters numerically; fallback, omission, gradient fallback, registration/mismatch rejection, batching and retirement are checked explicitly. The [Win32 menu host](#implemented-win32-vulkan-example-host) animates an aurora backdrop from its own clock and presents only while it is shown.

### Implemented linear gradients

[`LinearGradient`](../../include/tessera/style/gradient.hpp) holds `start`, `end`, `start_color`, `end_color` and an owned `stops` vector of `GradientStop{offset, color}`. Endpoints are fractions of the untransformed border box, each coordinate finite in [0, 1]; reversed endpoints are valid. An empty vector retains the original two-color shorthand at positions 0 and 1. A nonempty vector replaces those colors and needs at least two stops with finite offsets in [0, 1], in nondecreasing order. Positions need not include 0 or 1: the first/last colors extend outside the stop range. Duplicate offsets create hard transitions: the first coincident color is approached from below, and the last wins at the offset and above. All-coincident stops are valid. No sorting or implicit redistribution occurs.

Coincident endpoints reject as `degenerate_gradient` at `end`; a one-stop vector or descending offset rejects as `invalid_gradient_stops` at `stops` or `stops/<i>/offset`. All colors (including shorthand fields) and coordinates use ordinary located numeric diagnostics. Stop color paths are `stops/<i>/color/<channel>`. Zero-area rectangles paint nothing.

`ResolvedStyle::background_gradient` and `DrawRect::gradient` are `optional<Gradient>`, where `Gradient` is `variant<LinearGradient, RadialGradient>`. Either fill replaces its solid background/color, rather than compositing over it. Gradient colors are ordinary sRGB-encoded, straight-alpha inputs. Decode RGB to linear light, premultiply each stop by its alpha, interpolate RGB and alpha between the surrounding stops, then source-over blend. Linear fills use the clamped local projection `dot(p - start, end - start) / dot(end - start, end - start)`; projection endpoints scale by the rectangle's logical width/height, so diagonal gradients respect aspect ratio. Transparent stops contribute no hidden RGB. Opacity attenuates every stop alpha before interpolation.

CPU and both Vulkan paths implement this fill inside the same rounded-rectangle coverage, before the existing per-edge inside border and children. Transform, clip, scrolling and fractional-scale rules are unchanged; clipping never restarts the gradient. Both backends locate surrounding stops with upper-bound lookup, avoiding division by zero at duplicate offsets.

Vulkan retains the 112-byte primitive ABI and the shorthand's inline colors. Explicit stops use a per-frame owned storage buffer (32 bytes per stop), shared across rectangles and retained through host retirement in both reference and batch paths. A renderer-owned dummy binding satisfies the shader's static descriptor declaration for frames without explicit stops. The per-submission stop capacity is the smaller of `maxStorageBufferRange / 32` and 2^24 (exact float indices); exceeding it returns `gradient_stop_limit` at `/commands/<i>/gradient/stops`. Offsets or nonzero adjacent gaps requiring subnormal shader arithmetic return `gradient_stop_precision` at the stop offset. Unrepresentable projection coefficients return `geometry_overflow` at `/commands/<i>/gradient`. Rejection records nothing, retains counters/uploads and permits retry with the same frame number. There is no silent solid fallback. Fill-boundary antialiasing is opt-in through [analytic fills](#implemented-analytic-fills).

The [Inspector card](../guides/inspector-hierarchy.md) is the practical consumer. [CPU tests](../../tests/render/cpu_renderer_tests.cpp) check exact pixels, transparent/nonuniform stops, clamping, duplicate/exact-boundary transitions, aspect ratio, transforms and clips; [Vulkan tests](../../tests/render/vulkan_tests.cpp) compare shorthand, multi-stop (including a 65-stop fill) and hard-transition scenes through both paths and repeated frames with CPU at scales 1, 1.25, 1.5 and 2, using the existing 2/255 linear-channel tolerance. They also check rejection and partial/full upload retirement.

### Implemented radial gradients

[`RadialGradient`](../../include/tessera/style/gradient.hpp) holds `center`, `radius`, `start_color`, `end_color` and owned `stops`. Center coordinates are finite fractions in [0, 1] of the untransformed border box; the default is `{.5, .5}`. `radius.width` and `radius.height` are finite, strictly positive fractions of the box width and height, defaulting to `{.5, .5}`. Values above 1 are valid. Equal fractions produce an ellipse on a nonsquare box; a circle requires equal logical radii. Zero/negative radii reject as `out_of_range` at `radius/width` or `radius/height`; nonfinite geometry uses `invalid_number`.

For box-local position `p`, center `c = center * box_size` and ellipse radii `r = radius * box_size`, progress is `min(hypot((p.x-c.x)/r.x, (p.y-c.y)/r.y), 1)`. It is 0 at the center and 1 on/outside the ellipse. The shared stop ordering, duplicate-offset transitions, endpoint extension, two-color shorthand and premultiplied linear-light interpolation above apply unchanged. No focal point, repeating spread or implicit radius selection is introduced.

Style declarations and theme tokens accept either `Gradient` alternative through the same property; assigning radial replaces linear without an extra layer or clearing step. Explicit empty `optional<Gradient>` clears either. Paint owns its faded copy, keeps rounded coverage and inside-border/child order, and does not change layout or hit testing. Transforms carry the ellipse; clips and scrolling never recenter it. Zero-area boxes paint nothing.

CPU and Vulkan reference/batch implement this contract. Vulkan stores center and reciprocal normalized radii inline in the existing primitive, with the same optional stop buffer and frame retirement. A reciprocal outside finite normal binary32 range rejects as `geometry_overflow` at `/commands/<i>/gradient` before recording or consuming a frame. CPU has no shader-precision restriction. The shader clamps distance components before taking saturated length to avoid overflow. No fallback is substituted.

Owner tests cover exact elliptical pixels at four scales, transparent colors, interior/coincident stops, borders, transforms/clips, invalid geometry and Replay v1/v2. GPU comparisons include shorthand, 65-stop, hard-transition and rotated/skewed fills, repeated frames and rejected submissions at the same 2/255 linear-channel tolerance. The [Inspector card](../guides/inspector-hierarchy.md#gradient-property-card) uses an off-center blue/cyan/lilac highlight; it checks actual radial pixels against both two-color and linear substitutes.

## Implemented frame contract

[renderer.hpp](../../include/tessera/render/renderer.hpp) defines `FrameInfo` (a nonzero frame number strictly increasing per renderer, positive logical size, positive device scale in physical pixels per logical unit) and the abstract `UiRenderer`:

- `submit(frame, list)` borrows both arguments for the call only. A backend copies or encodes everything it needs before returning. Invalid input returns diagnostics and records nothing.
- Images referenced by frame N stay valid until the host calls `retire(M)` with M >= N. The host, which owns queues and fences, calls `retire` after observing GPU completion. A backend may reclaim its own upload memory for retired frames.
- The host provides the device, queues, render target, and presentation through the concrete backend's own construction or host-context API, never through core types. Target format, color-space conversion, resize, and device-loss behavior are specified per backend.

Concrete-backend validation is recorded in [support](../reference/support-matrix.md), separately from this interface contract.

### Implemented box shadows

[`BoxShadow`](../../include/tessera/style/shadow.hpp) supplies a finite logical `offset`, nonnegative finite `softness`, an ordinary sRGB straight-alpha `color`, and `inset` (default false). `ResolvedStyle::box_shadow` is optional and does not inherit. Declarations and theme tokens use the same explicit replacement/clearing rules as gradient fills; replacing one shadow also replaces its outer/inset mode.

For an outer shadow, paint emits an owned `DrawShadow` before the node's background, inside border and children. Its `rect` is the border box translated by the style offset; the command's own `offset` stays zero. `corner_radius` comes from the caster style and clamps to half the smaller dimension. Shadow bounds extend by `softness` on all sides. Layout allocation, scroll extents, semantics and rectangular hit testing do not expand. The shadow uses the caster's ancestor clip, not a new clip to its own border box; pane/window clips can trim the halo. Transforms carry both caster and falloff in local logical coordinates, and fractional scales sample at the ordinary pixel centers.

For local point `p`, box size `size` and clamped radius `r`, let `q = abs(p - size/2) - (size/2 - r)` and signed distance `d = length(max(q, 0)) + min(max(q.x, q.y), 0) - r`. Positive softness uses `t = clamp(d / softness, 0, 1)` and coverage `1 - t*t*(3 - 2*t)`: full caster coverage inside, smooth finite falloff outside, zero at/beyond the outer limit. Zero softness preserves existing hard rounded coverage. Zero-area boxes paint nothing. This is a distance-based shadow, not Gaussian blur, spread, multiple-shadow composition or group opacity. Translucent fills can reveal an outer shadow beneath them.

For an inset shadow, paint emits `DrawShadow` after the background and before the inside border, text and children. `rect` remains the unshifted border box, `inset` is true and the command's `offset` translates a same-size rounded cutout. Coverage is first clipped to the unshifted rounded box, then uses the signed distance at `p - offset` with `t = clamp(-d / softness, 0, 1)`. It is full outside the cutout, fades toward its interior and reaches zero at an interior distance of `softness`. Positive offsets darken the top/left side; negative offsets darken the bottom/right. Zero softness paints only points outside the translated cutout; an unshifted hard inset paints nothing, including the coincident boundary. Inset bounds never expand, even with a distant cutout or large softness. Existing ancestor clips, transforms, layout and input remain unchanged. This clips to the border box, not a CSS padding-box inset-shadow model.

CPU and Vulkan reference/batch apply coverage to source alpha and source-over blend in linear light. Ancestor/node opacity attenuates shadow color alpha without changing RGB. Vulkan modes 9 (outer) and 10 (inset) reuse the existing 112-byte primitive and require no texture, offscreen pass or additional resource buffer; batch uploads retire normally. Replay v1/v2 styles encode `inset: true` only for inset shadows; an absent or explicit false flag means outer, preserving pre-inset canonical bytes. Nonboolean flags reject as `schema_type`.

Validation reports nonfinite offset/softness/color as `invalid_number`, negative softness and invalid color components as `out_of_range`, under `box_shadow` for styles. Draw commands also validate their box, corner radius and inset cutout offset; nonzero command offsets on outer shadows reject as `out_of_range` at `/commands/<i>/offset` instead of being ignored. Unrepresentable expanded outer or unshifted inset bounds reject as `geometry_overflow` at `/commands/<i>/rect`; unsafe outer offset sums reject paint at `/nodes/<i>/box_shadow/offset`. Vulkan additionally rejects unrepresentable distance/intermediate bounds or a positive softness reciprocal outside normal finite binary32 at `/commands/<i>/softness`. Rejected submission records nothing and preserves frame/upload state for retry; no hard-shadow fallback is substituted.

Owner checks cover style/theme replacement, clearing and invalid values, paint order/opacity/clips and unchanged layout, exact outer/inset CPU falloff, hard/rounded/empty boxes, transparent alpha, clipping, transforms and Replay v1/v2. Vulkan compares reference/batch/repeat with CPU at scales 1, 1.25, 1.5 and 2 under the existing 2/255 linear-channel tolerance, including mirrored/skewed/rotated shadows and rejection/retirement. Its inset fixture uses byte-aligned midtone fills to avoid source-color half-byte rounding ambiguity and keep attachment quantization within that linear tolerance; it does not certify bright Inspector GPU pixels. The [Inspector card](../guides/inspector-hierarchy.md#card-shadow) verifies actual CPU pixels beneath its retained radial fill, and the [name input](../guides/inspector-hierarchy.md#name-input-inset-shadow) verifies its white-filled inset while preserving outside and center pixels.

### Implemented outlines and dashed strokes

[`Outline`](../../include/tessera/style/outline.hpp) is optional, noninherited paint decoration in `ResolvedStyle` and `StyleDeclarations`. Its `width` (default 1), outside `offset` (default 0), sRGB straight-alpha `color`, `dash_length`, `gap_length` and signed `dash_offset` are logical units. Width, offset, dash and gap must be finite and nonnegative; phase must be finite. A positive gap requires a positive dash length (`invalid_dash` at `dash_length`). A zero gap means a solid stroke; zero width or an empty box paints nothing. An absent declaration preserves the current outline; an explicit empty `optional<Outline>` clears it. Theme bindings use the same optional type.

Paint expands the border box by `offset + width` on each side and emits an owned [`DrawStroke`](../../include/tessera/render/draw_list.hpp) after the existing border, before text and children. Square boxes retain square joins; rounded boxes first clamp their radius to half the smaller box side, then add the expansion. The outline never changes layout, padding, hit testing or scroll allocation. Recorded ancestor clips still trim the decoration; its own overflow does not clip its outline. Unsafe expansion rejects the complete paint list with `geometry_overflow` at `/nodes/<i>/outline`.

Direct `DrawStroke` geometry describes the **outer** rectangle and radius. Clamp radius to half the smaller side and effective width to half that side. Subtract an inner rectangle inset by the effective width, with radius `max(0, clamped_radius - width)`; collapsed inner dimensions leave the outer shape filled. Dashes project samples onto the inset centerline and use clockwise arclength, starting at the top-left top tangent (the top-left centerline corner for square joins). Lines and quarter-circle arcs share one continuous phase; clips never restart it. Normalize `(arclength + dash_offset)` by `dash_length + gap_length`; positions below `dash_length` are painted. Positive phase advances the pattern. Ends are butt cuts; square corners use the nearest edge with top/right/bottom/left tie order. The closing seam may truncate or merge a dash; there is no automatic perimeter fitting, arbitrary path, rounded dash cap or custom join.

CPU and Vulkan reference/batch evaluate a fixed 4x4 grid per physical pixel, with offsets `{-3/8, -1/8, 1/8, 3/8}` on both axes. Transform each physical sample directly back to local coordinates before shape/pattern testing, then multiply source alpha by covered-sample count / 16 and blend in linear light. This is bounded supersampling of analytic geometry, not exact area coverage or hardware MSAA; very small strokes can fall between samples. The raster quad/bounds include a half-pixel coverage fringe so outer-edge samples are not lost. Vulkan reconstructs samples from fragment position and flat transforms, avoiding raster-quantized local interpolation. Clips retain their existing whole-pixel center rule. Existing `DrawRect`, `DrawBorder`, gradients, shadows, images and glyph behavior remain unchanged.

Vulkan mode 11 retains the 112-byte primitive ABI and ordinary frame/batch retirement, with no new texture or buffer. Unrepresentable expanded bounds, nonnormal shader transform determinants/scale reciprocals, subnormal positive stroke geometry or dash lengths, overflowing perimeter/period arithmetic, and more than 2^20 dash periods in the bounding rectangular perimeter reject as `geometry_overflow` at `/commands/<i>` before recording or changing frame/upload state. CPU uses scalar double arithmetic without those shader precision limits. No hard-edge or solid fallback is substituted.

Owner checks cover typed styles/themes and clearing, paint order/opacity and unchanged layout, exact half/quarter-pixel and sample-boundary coverage, rounded/clamped/collapsed shapes, continuous dash phase, clipping/mirroring, alpha and Replay v1/v2 initial/reloaded styles. Vulkan compares reference/batch/repeat at scales 1, 1.25, 1.5 and 2 with CPU within the unchanged 2/255 linear-channel tolerance, including square/rounded thin strokes, exact sample-grid edges, clip/skew/rotation and rejected submission/retirement. The [Inspector focus outlines](../guides/inspector-hierarchy.md#focus-outlines) provide the ordinary CPU-host consumer.

## Coordinate conversion

`FrameInfo::device_scale` expresses physical pixels per logical unit. Layout and draw geometry follow [logical coordinates](layout.md#coordinate-spaces); the renderer/host boundary converts them to the physical framebuffer and backend viewport/scissor conventions. Framebuffer extent, rounding, clip-edge conversion, and resize handling follow the concrete backend.

### Implemented continuous-coordinate policy

The [paint generator](../../src/render/paint.cpp), [glyph atlas preparation](../../src/render/glyph_atlas.cpp), and [Vulkan renderer](../../backends/vulkan/renderer.cpp) preserve continuous logical edges, glyph origins, and advances. Device scale changes raster size and sampling; it does not snap layout, border widths, or baselines to integer pixels. Vulkan coverage and scissors use the pixel-center rule below, and native pointer mapping uses that same center. The extent rounds outward with `ceil(logical_size * device_scale)`. A fractional border can cover different pixel counts as scale changes; this is coverage under the declared policy, not a geometry mutation. Independent rounding of neighboring boxes or text would break shared layout/hit geometry and is not part of this policy.

The [GPU fixtures](../../tests/render/vulkan_tests.cpp) verify fractional scales, noninteger padding and mixed-script baselines against independent raster sampling. An opt-in snap policy would require shared paint/hit geometry and a separate contract before use.

Validate fractional scales and scale changes as well as 1:1 rendering. Normalized input must map back to the same logical space. World-space projection belongs to a host adapter. The [Win32 example host](#implemented-win32-vulkan-example-host) defines one concrete logical-size and pointer-pixel mapping.

## Paint boundary

```text
retained nodes -> resolved style -> layout -> paint -> UiDrawList
-> backend draw packets -> GPU submission
```

The UI layer generates resolved drawing data. Backends consume that data without evaluating components, selectors, layout, events, or application state.

### Implemented paint generation

[paint.hpp](../../include/tessera/render/paint.hpp) defines `PaintInput` and `build_paint_list(PaintInput)`. One pass borrows the immutable `UiTree`, one `ResolvedStyle` per tree node indexed by `NodeHandle::index`, its `LayoutResult`, and the same `TextShaper` used for layout. The returned `UiDrawList` owns all commands and glyph data and can outlive those inputs. No tree handle, backend object, asset lookup, or application callback is stored in the output.

- **Order and geometry.** Walk displayed boxes in tree preorder. Each box emits its optional outer shadow (`DrawShadow`), solid or gradient background (`DrawRect`), optional inset shadow (`DrawShadow`), inside border (`DrawBorder`), optional outside outline (`DrawStroke`), then Text (`DrawGlyphRun`), before its children; later siblings paint above earlier subtrees. Backgrounds and inset clipping use `border_box`, outer shadows translate that caster box by their offset, borders use its recorded per-edge widths, and all preserve `corner_radius`; outlines expand under their [stroke contract](#implemented-outlines-and-dashed-strokes). Text is shaped using its required `text` string property, resolved `TextStyle`, and `TextConstraints::max_width` equal to `content_box().size.width` under the [text contract](text.md#implemented-boundary), and placed at `content_box().origin`; the shaper's glyph positions and metrics are preserved.
- **Alpha.** Each command's straight alpha is multiplied by the product of the node's and all ancestors' resolved opacity. RGB is unchanged. This per-command attenuation does not provide offscreen group composition; overlapping descendants can produce different pixels from group opacity.
- **Eligibility.** Display-none subtrees have no boxes. A hidden box suppresses its own commands; visibility is local in the supplied resolved styles, so an explicitly visible descendant can still paint. Ancestor opacity continues to apply through hidden boxes. Transparent shadows, backgrounds, borders, and text emit nothing; borders with all zero widths and runs with no glyphs emit nothing. Hidden or zero-opacity boxes and transparent Text do not call `shape`.
- **Clips and overflow.** Commands remain in root logical coordinates. Each emitting box's commands are enclosed in a `PushClip` of its recorded [layout clip](layout.md#implemented-prototype-algorithm); consecutive emitting boxes with the same clip share one push/pop pair, so generated clips never nest. Unclipped overflow paints in place. There is no implicit viewport clip, transform, image emission, z-index, or custom paint callback. [Scroll offsets](layout.md#implemented-prototype-algorithm) arrive already applied to recorded geometry and clips, so scrolled content needs no paint-side transform and shares hit testing's geometry. Transforms remain available to direct draw-list authors; transformed geometry must share its semantics with hit testing.

`validate(PaintInput)` rejects missing tree/layout/shaper (`missing_input` at `/tree`, `/layout`, `/text`), a wrong style count (`style_count` at `/styles`), and invalid styles under `/styles/<index>`. It reconstructs the displayed topology and requires exactly one box per displayed node (`layout_count` at `/layout/boxes`), matching live handles in preorder (`layout_node`), and matching layout parent indices (`layout_parent`). Border/padding/visibility must agree with the current styles (`layout_style`), and each recorded clip must equal the clip derived from its parent's geometry and overflow (`layout_clip` at `/layout/boxes/<index>/clip`). Scroll geometry must be present exactly on `overflow: scroll` boxes, with a finite extent that covers the padding box and an offset within `[0, scroll_limit()]` (`layout_scroll` at `/layout/boxes/<index>/scroll`). Box numeric diagnostics use the draw-list geometry rules under `/layout/boxes/<index>`; derived content geometry must also be finite. Invalid input returns no value and never calls the shaper.

The caller must recompute layout after any geometry or text/font change. Validation catches topology and recorded-edge/visibility mismatches; the result does not store a style fingerprint, so it cannot detect every stale dimension or text metric.

Shaping diagnostics are prefixed with `/nodes/<NodeHandle::index>`. A failed shaper returning no error diagnostic receives `text_shape_failed` at `/nodes/<index>/text`. Generated commands are validated before returning; malformed glyph data is located under `/nodes/<index>/commands/<local-command-index>`. Any error discards the entire list, including commands from preceding nodes. Successful shaping warnings are preserved with the owned list. Placeholder runs remain test data, not real font evidence; the optional backend's explicitly enabled placeholder path is defined below.

Non-rectangular clip shapes, transformed clipping, blend modes, and offscreen composition remain open decisions. Extend command coverage only with evidence.

### Implemented frame-local glyph atlas

[glyph_atlas.hpp](../../include/tessera/render/glyph_atlas.hpp) defines `prepare_glyph_atlas(list, cache, device_scale, first_image, limits)` in core. It borrows the [grayscale cache](text.md#implemented-grayscale-raster-and-cache-contract) only during preparation, returning an owned `GlyphAtlasFrame` with coverage pages and a draw list. Layout and paint still produce positioned `DrawGlyphRun` commands. The host explicitly prepares their resources before backend submission; no font library or GPU object enters this API.

- **Lowering.** Validate the entire source list, scale, limits, handle range, occurrence count and physical em sizes before requesting rasters. Round `run.size * device_scale * 64` after checking the inclusive 1..512 physical pixel range. Request each glyph's actual face, ID and size from the cache; repeated keys within a call share a placement, including empty glyphs. No face/policy replacement is allowed during the call, and a host reshapes old runs before preparing against a changed face. Raster diagnostics are prefixed with `/commands/<i>/run/glyphs/<g>` at the first occurrence of that key. A failed preparation returns no partial frame; already fetched cache entries may remain.
- **Packing and bounds.** `GlyphAtlasLimits` defaults to square 256-pixel pages, at most 16 pages, and 4096 glyph occurrences (including repeated/empty glyphs). Page size is 4..2048, page count 1..64, and occurrence limit positive. Pack non-empty rasters in first-use order, left to right in shelves, then downward, then into a new page. Copy coverage unchanged, with one transparent texel on every side and zero coverage in unused space. Empty glyphs allocate no region/page. Oversized rasters fail as `glyph_atlas_size`; exhaustion is `glyph_atlas_full`; occurrence overflow is `glyph_limit`. There is no persistent atlas, eviction, region reuse, or throughput claim. Every preparation has independent owned page bytes.
- **Commands and placement.** Replace each glyph run with ordered `DrawImage` commands and preserve every other command, including clips, transforms and existing images. A glyph's rectangle is `origin + glyph.position + (left/scale, -top/scale)`, sized `(width/scale, height/scale)`, without baseline snapping or advance changes. The normalized source rectangle covers the ink region; tint retains the run's color and straight alpha. Empty glyphs draw nothing. Unsafe baseline/bearing/extent sums fail as `geometry_overflow`; raster/validation failures retain actionable paths. The raster size uses device scale only; additional affine scaling transforms the prepared bitmap rather than rerasterizing at its effective scale.
- **Handles and lifetime.** The host reserves `limits.pages` consecutive nonzero image handles from `first_image`, disjoint from existing source images and any live host binding. Zero/overflowing ranges fail as `invalid_handle`; source collisions as `image_collision`. Actual pages use the beginning of that range. Output owns its commands and coverage and can outlive the cache or font service. The host treats pages as immutable after preparation, uploads/binds them before drawing, and preserves GPU resources/bindings through completion and retirement. New frames can use independent handles while older frames remain live; changing CPU pages never authorizes reuse of live GPU regions/descriptors.
- **Sampling.** Upload coverage as straight alpha with constant white RGB, one mip level, linear min/mag filtering, and clamp-to-edge. RGB is white even in the transparent gutter, so bilinear filtering cannot darken text color. Alpha is linear coverage and receives no sRGB decode. The gutter isolates neighboring regions; placement does not alter sampling. Backends continue consuming ordinary `DrawImage` commands under their image/frame contracts. Hosts own image upload, transitions, synchronization and destruction; no renderer-specific upload convenience API is introduced.

[Core fixtures](../../tests/render/glyph_atlas_tests.cpp) verify packing, lifetime, bounds and failure atomicity. When both optional Vulkan and fonts modules are enabled, [GPU fixtures](../../tests/render/vulkan_tests.cpp) upload these pages and sample original rasters independently of atlas placement, including wrapped mixed-script paint. That independent sampler is a fixture oracle; the [CPU reference backend](#implemented-scalar-cpu-reference-backend) uses ordinary atlas images. Exact configuration/tolerances belong in [support](https://github.com/animu-sphere/tessera/blob/cf86d0992d0f81f606b557e46ad0ddcba758eaf7/docs/reference/support-matrix.md#glyph-atlas-and-vulkan-image-evidence--2026-10-08).

## Host integration

The host owns the GPU device, queues, window, frame scheduling, and presentation. The concrete backend owns its pipelines, descriptor/binding data, UI uploads, and command generation. An example host can own a standalone device/window; that does not transfer those responsibilities into the UI core.

CPU data and resource lifetimes follow the frame contract above: GPU-visible resources cannot be reclaimed before `retire` covers their last frame. Each backend specifies synchronization, resize, resource replacement, and device-loss behavior rather than relying on hidden global state. Borrowed-device integration and standalone examples must obey the same ownership rules.

## Backends and shaders

The optional Vulkan module is defined below. WebGPU is the intended rendering boundary for the [Web host](../proposals/web-host.md), with native WebGPU evaluated separately. The [CPU reference backend](#implemented-scalar-cpu-reference-backend) is explicitly constructed by the host. Metal and Direct3D 12 require a concrete consumer. Scheduling belongs in backlog and configuration evidence in support.

`UiDrawList` is the backend-neutral render IR: every backend consumes the same commands, and layout, style, shaping, glyph selection, clips, and transforms are settled before submission. Only rasterization differs per backend. A separate display list or render IR is introduced only with a defined consumer, as stated under [batching](#batching).

Slang compiles the Vulkan [primitive shader](../../backends/vulkan/shaders/primitive.slang) below `UiDrawList`; ordinary components do not refer to shader entry points or pipeline objects. It is a build tool for this module, not a core requirement. The [module build](../../backends/vulkan/CMakeLists.txt) emits separate SPIR-V 1.3 reference vertex, batch vertex, solid fragment, and image fragment artifacts, preserving entry-point names. `SV_VulkanVertexID` avoids requiring the optional draw-parameters feature; see the [Slang SPIR-V mapping](https://docs.shader-slang.org/en/latest/external/slang/docs/user-guide/a2-01-spirv-target-specific.html). Shared vertex/coverage code lives in `primitive_common.slang`; host-authored [procedural fills](#implemented-procedural-fills) compile against `procedural.slang` into separate fragment artifacts.

Reassess shader-source strategy for WebGPU, including WGSL suitability, against its selected toolchain. Adopted choices belong in [dependencies](../reference/dependencies.md), validation in [support](../reference/support-matrix.md).

### Implemented Vulkan primitive boundary

[renderer.hpp](../../backends/vulkan/include/tessera/vulkan/renderer.hpp) defines `VulkanRenderer`, available through `tessera::vulkan` only when `TESSERA_BUILD_VULKAN=ON`. Its header exposes Vulkan types within this optional module; core headers remain SDK-independent. It records commands and never submits queues, waits on the host, or presents.

- **Construction and ownership.** `VulkanContext` borrows the host physical/logical device and compatible render pass, with subpass 0 containing one single-sampled color attachment. The host enables Vulkan 1.1 or newer. Only `R8G8B8A8_SRGB` and `B8G8R8A8_SRGB` are accepted. SPIR-V spans are borrowed during construction only. The renderer owns three reference pipelines (solid, straight-alpha image and premultiplied image), three additional pipelines when batching is enabled, a pipeline layout, descriptor layout, and bounded image descriptor pool. Unsupported construction arguments throw `std::invalid_argument`; Vulkan creation/allocation failures throw `std::runtime_error` carrying the failing operation/result. Construction cleans up partially created objects. The host completes and retires all frames before destroying the renderer, then may destroy its borrowed device/pass/resources. No internal queue wait or device-loss recovery occurs.
- **Target and submission.** `set_target` borrows a command buffer already recording inside the compatible render pass and a physical extent. `submit` validates the entire frame/list, image bindings, composed/transformed numeric bounds, and target before recording anything or updating image use. It rejects stale frame numbers (`stale_frame`), missing/unsupported target extents (`invalid_target`), extent mismatch (`extent_mismatch`), unsafe float intermediates (`geometry_overflow`), unknown images (`invalid_handle`), and glyph commands without explicit placeholder opt-in (`unsupported_command`). Rejection leaves frame numbers and resource use unchanged. Successful calls set viewport/scissors/pipelines/push constants/descriptors and emit commands in authored order. This changes command-buffer graphics state; a host rendering afterward must rebind its state. Calls are single-threaded and not reentrant.
- **Coordinates and clips.** Extent must equal `ceil(logical_size * device_scale)` per axis, computed in double from the supplied float values. The host calls `set_target` again after resize; pipelines can remain when pass/format compatibility is unchanged. Affine transforms compose in authored order. Clips become physical continuous axis-aligned bounds, including negative-axis transforms, intersect before rounding, and include a pixel when its center lies inside the half-open bounds: edges become `ceil(edge - 0.5)`, clamped to the framebuffer. A clip edge therefore covers exactly the pixels a primitive edge at the same position covers, and agrees with pixel-center pointer mapping. Empty intersections and zero-area primitives emit no draws. Clip/transform pops restore the complete previous state. Rotated/skewed clips remain rejected by common draw-list validation; rotated/skewed primitives are accepted.
- **Primitive pixels.** A six-vertex quad carries local coordinates; fragments discard outside circular rounded corners. Radius clamps to half the smaller side. Borders subtract an inset rounded inner rectangle; its radius is `max(0, authored_radius - max(edge_widths))`, then clamps to the inner dimensions. If inner dimensions collapse the whole outer shape is filled. This is the prototype's explicit unequal-border corner rule. Existing primitives remain hard-edged; only the opt-in [stroke command](#implemented-outlines-and-dashed-strokes) uses 4x4 coverage. No hardware MSAA or pixel snapping is introduced. RGB command colors convert from sRGB to linear; straight-alpha source-over blending occurs in the sRGB attachment's linear domain before attachment encoding, except for premultiplied images below. Solid and image pipelines cover the commands. The default reference path keeps each primitive a separate draw and reuses adjacent pipeline binds; the optional instance path follows [batching](#batching).
- **Images and retirement.** `bind_image` associates a nonzero neutral handle with borrowed host `VkImageView`/`VkSampler` from the same device; views expose linear RGB to the shader (normally an sRGB view for encoded assets). Its optional `ImageAlpha` argument, declared with `ImageHandle` in [draw_list.hpp](../../include/tessera/render/draw_list.hpp), fixes how samples relate to alpha for that binding: `straight` (the default) samples straight alpha; `premultiplied` samples RGB already multiplied by alpha and blends it source-over with source factor one, without unpremultiplication. Unknown values return `unknown_value` at `/image/alpha`. The host uploads/transitions the image to `SHADER_READ_ONLY_OPTIMAL` and maintains that state and object lifetime through retirement. The source rectangle must fit normalized [0,1] coordinates; tint uses the same linear color/straight-alpha rules, and on a premultiplied image its alpha also scales the sampled RGB, so the result stays premultiplied. `max_images` bounds live bindings (`image_limit`). Rebind/unbind returns `resource_in_use` until the last successful referencing frame is retired, including clipped/zero-area image references. Unknown unbinds fail. `retire` advances monotonically, clamps to the last successful frame, and does not authorize resource changes in future frames. The host calls it only after observing completion of every covered frame. Replacement updates only retired descriptors; no external asset loading API is implied.

Real font runs can use the explicit [atlas preparation](#implemented-frame-local-glyph-atlas) path and host-owned image uploads with this image pipeline. Direct `DrawGlyphRun` submission uses only the placeholder opt-in below. The backend defines no device-loss recovery. Swapchain presentation is host work; see the [Win32 example host](#implemented-win32-vulkan-example-host).

### Implemented Vulkan placeholder Text

`VulkanContext::placeholder_text` defaults false. When enabled, the host promises every `DrawGlyphRun` was produced by `PlaceholderTextShaper` with default `FontId` 0. The backend cannot infer the shaper from numeric glyph IDs. Nonzero font IDs fail with `unsupported_font` at `/commands/<index>/run/font`; surrogate IDs and IDs above U+10FFFF fail with `invalid_glyph` at `/commands/<index>/run/glyphs/<index>/id`. No real font, fallback service, atlas, or additional GPU resource is introduced.

The original [5x7 bitmap marks](../../backends/vulkan/placeholder_glyph.hpp) cover ASCII letters/digits and `. , : - _ + / ! ? ( )`. Lowercase uses uppercase shapes. Space draws nothing; other Unicode scalars use an outlined missing-glyph box, including Japanese characters. This is a legible menu/test placeholder, not Latin/Japanese font support.

Each non-space glyph emits one solid-pipeline quad. Its top left is `command.origin + glyph.position + (0.05 em, -0.8 em)`; size is `(0.4 em, 0.7 em)`, using `GlyphRun::size`. Rows are supplied in per-primitive data and the fragment shader discards unset cells. Placement honors the shaper's baseline pen positions, including explicit line heights and multiline runs, without deriving positions from run metrics. It preserves the placeholder shaper's 0.5 em advance. Cells have hard edges, with no antialiasing or pixel snapping.

Glyphs inherit the current affine transform, physical scissor, authored order, and linear-light straight-alpha blending. Origin/pen sums, quad bounds, and transformed intermediates are checked before recording, including whitespace and fully clipped glyphs. A rejected run records nothing, consumes no frame number, and does not pin preceding image references. Empty runs and spaces draw no pixels. Bitmap data is copied into command-buffer push constants on the reference path or retained instance uploads on the batch path; it needs no atlas retirement, and uses the existing host completion/destruction rule.

### Implemented Win32 Vulkan example host

[vulkan-menu](../../examples/vulkan-menu/main.cpp) is an example host built with the optional module on Windows (`tessera_vulkan_menu`). It is not a library API: window, OS input, DPI, instance/device/queue/surface/swapchain, synchronization, presentation, and retirement stay in the executable. The renderer receives only the borrowed context, a recording command buffer, `FrameInfo`, and the owned paint list.

- **Document path.** An embedded JSON v1 menu becomes a `UiTree` whose buttons carry the `button` class; a host-built `StyleSheet` and the current hover/active/focus state go through the [prototype resolver](styling.md#implemented-prototype-style-resolution). Layout and paint borrow the same text service. By default it is `PlaceholderTextShaper` with `VulkanContext::placeholder_text` enabled; the explicit font path below disables that opt-in. The host supplies the batch vertex artifact to enable adjacent batching. The screen background requests the `tessera.example.aurora` [procedural fill](#implemented-procedural-fills) built from [aurora.slang](../../examples/vulkan-menu/aurora.slang) (two-color wash plus one wave-shaped glow band, five typed parameters, phase 0.75 and `time_rate` 0.8 radians of wave phase per second); the host registers that artifact after constructing the renderer, and the flat screen color remains the declared fallback. A fixed-height `overflow: scroll` list partly clips its last button when unscrolled; the host owns its scroll offset and relays out when [wheel or focus reveal](input.md#host-boundary) changes it. The buttons are `focusable`, and their labels inherit text size and color. `.button:hover` and `.button:active` rules change only backgrounds and `.button:focus` only the border color; whenever resolved styles change after input, the host recomputes layout and paint.
- **Explicit font assets.** When built with the optional fonts module, `--fonts` accepts two native Unicode filesystem paths, reads nonempty files bounded to 64 MiB each, and registers their face 0 as Latin `FontId` 0 and Japanese `FontId` 1. It declares the `menu-latin`/`menu-cjk` families at weight 400 and binds logical ID 2, `ui-sans`, to that ordered stack under the [selection contract](text.md#implemented-family-and-logical-alias-selection). The root style inherits that logical font; glyphs retain concrete IDs 0/1. Asset loading stays in this executable; no system discovery or implicit substitution occurs. Missing, empty, oversized, or invalid font assets fail before window/GPU initialization; a build without fonts rejects the option. The real menu uses `Start スタート`, `Quit 終了`, and `Credits クレジット`; Start has a 70.1-unit content width to exercise wrapping, and the list has a 171.3-unit height. The smoke requires the two faces and raster/shaping settings in the [declared profile](text.md#declared-grayscale-fixture-profile), selected through the explicit alias.
- **Glyph uploads.** A host-owned `GlyphCache` borrows the real shaper for its lifetime. Each frame uses [atlas preparation](#implemented-frame-local-glyph-atlas) at the current device scale, with up to sixteen 256-pixel pages and 4096 occurrences. The two frame slots reserve disjoint consecutive handle ranges. The host copies coverage into white RGBA8 UNORM images with straight coverage alpha, one mip level, a linear clamp sampler, and transfer-to-shader-read barriers before the render pass on the same command buffer/queue. CPU pages can be discarded immediately after copying. Each slot retains its staging buffers, views, images, and bindings through its fence; after waiting and retiring that frame, it unbinds and frees them before reuse. Resize/DPI updates idle/retire and release every slot before the new layout/scale generates new rasters. Shutdown waits, retires, destroys renderer descriptors, then frees all glyph resources. This is frame-local upload, without persistent GPU caching or per-upload queue-idle waits.
- **Presentation.** One graphics queue family that also presents, an sRGB-nonlinear `B8G8R8A8_SRGB` (preferred) or `R8G8B8A8_SRGB` surface format, FIFO, and two frames in flight. Each slot owns a command buffer, acquire semaphore, and fence; each swapchain image owns its render-finished semaphore. After waiting a slot or image fence, the host calls `retire` with the last successful renderer frame submitted before that fence, because the fence also covers earlier submissions on the queue. A rejected submission still presents the cleared image and consumes no frame number.
- **Motion and frame scheduling.** A host animation clock counts shown seconds from the first shown frame, read from the same monotonic counter as input timestamps. Each loop iteration repaints at the clock's time only while the window is shown, the aurora is registered and the paint list is `time_dependent`; this is a paint-only update without restyle or layout. The host presents a frame only when paint changed, the swapchain was recreated or dirty, the window was exposed (`WM_PAINT`) or a smoke capture is pending. Otherwise it waits for messages, waking at most every 16 ms to poll the gamepad. Minimizing (or a zero client extent) pauses the clock and stops presentation; restoring resumes the clock where it paused, so motion does not jump by the hidden interval. An unregistered aurora requests no motion frames, since its fallback is static. Occlusion by other windows is not detected; the FIFO swapchain paces motion frames to the display.
- **Update point.** `WM_SIZE` and `WM_DPICHANGED` (scale = DPI / 96, suggested window rectangle applied) idle the device, retire every submitted frame, recreate the swapchain/framebuffers, recompute layout, reveal focus that the new layout hid under the [host reveal policy](input.md#host-boundary), and `refresh` the pointer and focus dispatchers before later input is mapped. A zero client extent suspends rendering. The swapchain extent is authoritative; each logical axis is the largest `float` whose `ceil(logical * scale)`, computed as the renderer does, equals the physical extent.
- **Pointer pixels.** Integer client pixel `(x, y)` maps to logical `((x + 0.5) / scale, (y + 0.5) / scale)`, the pixel center sampled by rasterization and by the scissor, so a pixel painted by a half-open border box inside its clip hits the same box. [Input](input.md#host-boundary) owns the message-to-event mapping.
- **Smoke readback.** `--smoke` requires the validation layer with synchronization validation, adds transfer-source usage to swapchain images, and reads selected frames back through a render pass that differs only in final layout (compatible passes carry identical dependencies). It posts mouse, wheel, capture-loss, cancel-mode, key, and synthetic `WM_DPICHANGED` messages through the window procedure, feeds scripted gamepad samples through the polling path in place of XInput, checks the host action sequence, focused node, the resolved `:active` background of a held button and `:focus` border of the focused one, and presented background/left-border pixels against the styles that produced them, and fails on validation errors or rejected submissions/events. The smoke replaces the clock source with a scripted one advancing 1/60 s per loop frame plus 1 s per sequence step. Backdrop pixels outside the panel must match an independent double-precision aurora evaluation at the shader time that frame's paint evaluated (itself checked against phase + rate * host time) within 3/255 encoded channels, differ visibly from the fallback, and differ by more than 6/255 from the evaluation at the previous capture's time; each frame must execute one procedural fill with no fallback. Before quitting, the smoke minimizes the window, advances the scripted source by 10 s and restores it from a timer: no frame may be presented and the clock may not advance while minimized, and the restored clock must continue within a second of where it paused before a final capture. Each capture compares every pixel within three rows of the list's bottom clip edge, and of its top edge when scrolled, with `hit_test` at that pixel's center; posted clicks on the rows just inside and outside the bottom edge must and must not activate the clipped button. It also checks that gamepad focus reveals the clipped button, a partial wheel delta scrolls the list, a click activates the scrolled button, and a wheel outside the list changes nothing.
- **Real-font smoke.** The combined configuration additionally runs that sequence with the explicit Noto assets. It checks measurement/paint metrics and assigned Text heights, two-line Start wrapping, per-label Latin/Japanese fallback without missing glyphs, live-image rebind/unbind rejection, and successful completed-slot release. Captured label interiors are compared with independent bilinear sampling of original glyph rasters at continuous baselines over their flat button backgrounds, with device subpixel quad coverage, layout clips, linear-light source-over, and a 2/255 linear RGB tolerance. This small oracle reads no atlas coordinates and is not a general CPU renderer. Clip scans distinguish antialiased button/text pixels from the flat panel backdrop. Primitive/placeholder offscreen fixtures and the original native smoke remain separate checks.

Separate present queues, device loss, automatic font discovery, word/Unicode line breaking, and kinsoku are not handled by this host. [Development](../guides/development.md#combined-font-and-vulkan-glyph-workflow) owns commands and artifact locations.

## Batching

### Implemented Vulkan adjacent batching

The optional [renderer](../../backends/vulkan/include/tessera/vulkan/renderer.hpp) enables batching when `VulkanContext::batch_vertex_spirv` contains the compiled `batchMain` vertex entry point; an empty span selects the individual-draw reference path. Both paths use the same validated ordered packets and fragment shaders. No core or JSON v1 contract changes.

- **Grouping and order.** Merge only consecutive emitted packets with the same solid/image/procedural pipeline, image handle (zero for solid), and identical physical integer scissor. Source-over blending is fixed per pipeline; a binding's image alpha selects the straight or premultiplied image pipeline, so equal handles never mix the two. Rectangle, border, and placeholder glyph modes, color, image crop/tint, and transform are per-instance values, so they can differ within a batch. Stack commands resolve into packet state before grouping; no sorting occurs. Empty/clipped commands emit no packet, but referenced images still obey the existing retirement rule. A batch records `vkCmdDraw(6, instance_count, 0, first_instance)` in packet order. Instance order and framebuffer blending obey Vulkan [primitive order](https://docs.vulkan.org/spec/latest/chapters/drawing.html#drawing-primitive-order) and [rasterization order](https://docs.vulkan.org/spec/latest/chapters/primsrast.html#primsrast-order).
- **Uploads and failure.** Each nonempty successful batch submission allocates its own host-visible vertex buffer with 112 bytes per emitted primitive; coherent memory is preferred, otherwise the entire mapped allocation is flushed before recording. No buffer is overwritten or reused across in-flight submissions. Host `retire` releases only uploads covered by its clamped completion value. Empty lists allocate no upload. All validation and allocations finish before any commands, image-use updates, or success counters change. Vulkan allocation/map/flush failures throw `std::runtime_error` with the failing operation/result; missing host-visible memory also throws. More than `UINT32_MAX` emitted primitives returns `primitive_limit` at `/commands` on either path. Hosts must regularly retire completed frames; retained upload count grows with unretired nonempty submissions. Pooling and timing claims are outside this contract.
- **Observations.** `submission_stats()` returns emitted `primitives`, recorded `draw_calls`, and payload `upload_bytes` for the last successful call; before success all are zero, and rejection preserves them. Reference uploads report zero bytes. Allocation padding is excluded. `pending_uploads()` reports retained batch buffers. These counters do not measure CPU or GPU duration. The native smoke checks batch reduction and its two-frame retention bound.

Keep the reference path for image comparison whenever grouping or packet encoding changes. Future blend modes must become batch keys before they can be merged.

`Canvas` / custom paint uses this command vocabulary and observes balanced clip/transform state. It must not bypass draw-list resource lifetime or depend on a concrete backend.

## Proposed primitive semantics

The [Look proposal](../proposals/look.md) separates shape/coverage, paint/material, effects, motion and composition. It explores gradients, shadows, analytic/SDF shapes and Slang procedural fills through resolved draw data, without changing the implemented command set above. Shader compilation and resource execution remain below the backend/host boundary; time comes from the host under [animation](../proposals/animation.md).

Use a hybrid renderer with techniques suited to the content. SDF is a useful shape implementation, not a required representation for the entire UI. Starting choices are:

| Content | Technique |
| --- | --- |
| Rectangles, rounded rectangles, borders, distance-based outer shadows; later circles, ellipses, capsules, focus rings | Analytic distance/coverage functions over one quad per primitive |
| Text | [Glyph raster strategies](text.md#proposed-glyph-raster-strategy): grayscale, MSDF, color glyphs |
| Vector paths | Path rasterization; distance-field representations remain an option where their quality and cost fit |
| Images | Texture/bitmap sampling |

Built-in primitives share defined visual semantics, including coverage and stroke rules. GPU, scalar CPU and optimized CPU implementations may use different algorithms while preserving those semantics under declared tolerances. A shared mathematical definition is useful where appropriate, such as the rounded-rectangle and unequal-border rules above; generating code from one description is optional. Backend-specific capabilities such as procedural fills declare support, diagnostics and an explicit fallback rather than requiring arbitrary Slang execution on CPU. A fallback is not evidence that the requested effect ran.

The pixel-center rule remains the baseline for existing primitives and clips. Opt-in [strokes](#implemented-outlines-and-dashed-strokes) and [analytic fills](#implemented-analytic-fills) add bounded 4x4 coverage without changing existing draw lists. Additional coverage methods, such as derivative-width GPU distance coverage or CPU area integration, require declared support and updated reference cases. Unsupported paths must be observable. Clip-edge changes also need a declared relationship to [hit testing](input.md#implemented-rectangular-hit-testing). Shape-aware input is opt-in with an independent CPU geometry contract; a custom shader does not silently replace layout-box input geometry.

New commands, shadows and paths follow useful consumer outcomes, without requiring every backend or later Look slice to land together. Nonrectangular clipping, group opacity, masks, blend modes and offscreen effects need their own composition/resource contracts when selected; they are not excluded by today's vocabulary. Subpixel LCD rendering depends on OS, display orientation and compositor and is a possible platform-specific option rather than the portable default.

## Implemented scalar CPU reference backend

[cpu_renderer.hpp](../../include/tessera/render/cpu_renderer.hpp) defines `CpuRenderer : UiRenderer`, `CpuTarget`, `CpuImage`, and `CpuFrameCapture : FrameCapture`; [cpu_renderer.cpp](../../src/render/cpu_renderer.cpp) implements them using the standard library in `tessera::core`. They consume ordinary draw lists without a window, GPU, filesystem, font implementation, or application-state dependency. Calls are sequential on one host thread.

- **Target and submission.** `set_target` borrows top-down, tightly packed RGBA8 sRGB bytes. The host owns their lifetime, clearing, resize and presentation; `submit` composites over their existing contents synchronously. Target extent equals `capture_extent(logical_size, device_scale)` and byte count is exact. Each target and image has positive dimensions and at most `max_cpu_pixel_bytes` (256 MiB). Frame/list, target, every image reference/crop, composed transforms and transformed geometry are checked before any pixels or resource-use records change. Rejection consumes no frame number. Located errors include `invalid_target`, `extent_mismatch`, `stale_frame`, `invalid_handle`, `out_of_range`, and `geometry_overflow`. Transform coefficients, inverse linear coefficients and physical bounds must be finite within float range, and composed determinants nonzero. Standard allocation failures remain exceptions.
- **Coverage.** Scalar double arithmetic preserves continuous geometry and device scale. Axis-aligned clips intersect continuous physical bounds before rounding by `ceil(edge - 0.5)`. Existing primitive quads use the framebuffer top/left inclusion rule, including rotations, skew and negative axes; no local-coordinate endpoint rule reverses coverage on mirrored primitives. Rounded corners clamp radius to half the smaller dimension. Inside borders subtract the same unequal-width inner shape as the Vulkan shader: inner radius is `max(0, radius - max(widths))`, clamped to inner dimensions; collapsed inner dimensions leave the complete outer shape. Inner fragment containment uses local half-open edges. Opt-in [strokes](#implemented-outlines-and-dashed-strokes) and [analytic fills](#implemented-analytic-fills) add 4x4 pixel coverage. There is no hardware MSAA, geometry snapping or GPU subpixel-position quantization.
- **Color and images.** Commands convert sRGB RGB to linear and retain straight alpha. Source-over RGB and alpha blend over target bytes, a premultiplied image's RGB with weight one, then each primitive's result is encoded and rounded to the nearest RGBA8 value, with half values rounded upward. `bind_image` copies exact pixels into an owned binding; `CpuImageEncoding::rgba8_srgb` decodes RGB before sampling, while `rgba8_unorm` treats RGB as linear. Alpha is linear in both. `CpuImage::alpha` carries the same `ImageAlpha` as the Vulkan binding: a premultiplied image's sampled RGB is scaled by tint alpha as well, and unknown values report `unknown_value` at `/image/alpha`. Bilinear min/mag sampling uses one level with clamp-to-edge, normalized source crops inside [0,1], linear tint multiplication and straight alpha. At most `max_cpu_images` (64) bindings and 256 MiB of aggregate image bytes are accepted (`image_limit`); malformed bytes/extent report `invalid_image`. Even clipped or zero-area references pin images through their last successful frame; `resource_in_use` rejects replacement/removal before `retire`. Retirement advances monotonically and clamps to the last submitted frame. CPU work is complete on return, so the host may retire immediately.
- **Glyphs and capture.** Direct `DrawGlyphRun` submission reports `unsupported_command`; hosts lower real glyphs through [atlas preparation](#implemented-frame-local-glyph-atlas). `CpuFrameCapture` borrows an optional `GlyphCache` and prepares atlas pages when glyph commands exist, finding a consecutive handle range disjoint from host bindings and source image references. White RGBA8 UNORM pages preserve grayscale alpha and share the ordinary image bounds. The adapter owns a transparent target, increasing renderer frame numbers, temporary page bindings, immediate retirement and an owned `CapturedImage`; temporary bindings and borrowed target pointers are cleared on failure or exception. A cache can retain entries fetched before a rejection. Without a cache glyph requests fail explicitly. Capture returns `capture_limit` for excessive target bytes, checks extent and paint inputs, and rejects recursive capture or image binding changes during raster callbacks as `reentrant_capture`. It declares backend/device identities `cpu-scalar` / `scalar-rgba8`, ignores wall time, and connects directly to the [offscreen runner](inspection.md#implemented-prototype-offscreen-runner).

[CPU checks](../../tests/render/cpu_renderer_tests.cpp) verify pixels, transforms/clips, owned images, retirement, atomic rejection, bounds, grayscale atlas cleanup and repeated runner output. [Vulkan checks](../../tests/render/vulkan_tests.cpp) compare both GPU paths with CPU captures under declared scales/tolerances. GPU subpixel quantization and interpolation at exact inner-border or glyph-quad pixel-center boundaries can change coverage; comparison fixtures state their edge conditions instead of weakening the pixel tolerance.

## Proposed CPU optimization

Performance work keeps the scalar result as reference: tile binning, worker threads over tiles, SIMD (SSE/AVX2/NEON class) for coverage, blending, sampling, and distance evaluation, and repainting only damaged tiles once dirty tracking is proven equivalent to full repaint. A deterministic mode with fixed tile ordering and order-independent results is the default for tests; a performance mode may schedule dynamically but must not change pixels beyond declared tolerances.

Pixel-free checks need no renderer: layout, hit testing, focus, semantics, inspection, and replay already consume tree, layout, and paint outputs directly. A no-op `UiRenderer` is introduced only when a host loop needs submission and retirement exercised without pixels.

## Proposed backend selection

The host constructs and selects the backend; core never chooses one. An application host may offer an automatic policy that tries its preferred GPU backend and falls back to the CPU backend, and it records which backend was selected so diagnostics and snapshot manifests can report it. Tests, CI, and capture runs declare the backend explicitly; an unavailable backend fails rather than falling back. Command-line switches and environment variables for selection are host or tooling choices, not core contracts.

## Implemented capture boundary

[capture.hpp](../../include/tessera/render/capture.hpp) defines a prototype completed-frame boundary in core, used by the [offscreen runner](inspection.md#implemented-prototype-offscreen-runner). It names no SDK object, window, or encoder.

- **Declaration.** `CaptureBackend` is the host's statement of what it constructed: a `backend` and a `device` identity, each 1–256 UTF-8 bytes without ASCII controls (`invalid_identifier` or `invalid_utf8` at `/backend` or `/device`), and a `CaptureFormat`. The only format is `rgba8_srgb`: top-down rows of tightly packed 8-bit RGBA with sRGB-encoded RGB and the target's alpha as read back (`unknown_value` at `/format` otherwise). Identities are fixture names compared exactly, not discovered or normalized device properties.
- **Extent.** `capture_extent(logical_size, device_scale)` is `ceil(logical * scale)` per axis computed in double, the [Vulkan target rule](#implemented-vulkan-primitive-boundary). Both inputs must be finite and positive (`invalid_number` or `out_of_range` at `/logical_size/width`, `/logical_size/height`, or `/device_scale`), and each axis must fit 32 bits (`out_of_range` at `/logical_size`).
- **Adapter.** A `FrameCapture` reports its `backend()` and implements `capture(CaptureRequest)`, which borrows the generation index, logical size, scale, extent, explicit animation-clock value, and paint list for the call. The adapter receives recorded time and does not advance it from wall time. It returns an owned `CapturedImage` only after the frame has completed on the host's device; it owns target allocation, any image resources such as [glyph atlas](#implemented-frame-local-glyph-atlas) uploads, renderer frame numbers, submission, completion, retirement, and readback. Calls are sequential and not reentrant. Rejected submissions return their diagnostics.

The [Vulkan fixtures](../../tests/render/vulkan_tests.cpp) implement an adapter over the reference path, keeping renderer frame numbers increasing across runs. It submits placeholder Text directly; with a glyph cache it [prepares atlas pages](#implemented-frame-local-glyph-atlas) for each generation, uploads and binds them before submission, and unbinds and destroys them after completion and retirement. The [CPU reference adapter](#implemented-scalar-cpu-reference-backend) owns its target and completes synchronously through the same capture interface.

## Proposed capture boundary

An offscreen host owns targets, submission, completion, and readback. A reusable capture service associates an image with the submitted frame/update generation, physical extent, scale, format/color convention, and backend/device metadata. CPU inspection and GPU completion must agree under the [snapshot bundle](../proposals/snapshot-bundles.md#proposed-runner-and-snapshot-bundle) contract. Readback does not weaken retirement requirements or add window/platform types to core.

Image encoding/export belongs to optional tooling, with explicit dependency/licensing choices. Existing fixture readback and PPM artifacts are examples of backend evidence, not a general PNG-capture API, runner, or CLI. Headless means no window: GPU capture requires a declared device, while the [CPU reference backend](#implemented-scalar-cpu-reference-backend) captures without one. Which backend produced an image is always declared.

## Proposed overlay paint

Implemented root-sibling [Popup/Tooltip placement](layout.md#implemented-anchored-popups) needs no alternate paint path: ordinary preorder draws popup subtrees after content, using their actual root clips. The [CPU fixture](../../tests/input/popup_tests.cpp) checks pixel/hit agreement beyond the anchor's scroll clip.

The implemented single [Modal/Dialog](layout.md#implemented-modal-placement) is the last root sibling and likewise uses ordinary preorder paint and shared clips. Its backdrop precedes its child panel; the [Modal CPU fixture](../../tests/input/modal_tests.cpp) checks backdrop pixel/hit agreement. No renderer-specific modal layer or Portal relocation is introduced.

The [overlay/portal model](../proposals/overlays-and-portals.md#proposed-overlays-and-portals) provides layer identity and presentation ancestry. Paint uses shared placement/clip geometry to place overlay commands after the appropriate content layer, without inheriting ordinary content clips accidentally. Define deterministic ordering and balanced stack boundaries; input must use the same presentation order. Portals do not bypass resource retirement or create backend-owned components.

## Assets

Fonts, images/icons, textures, style sheets, UI documents, and future vector assets come through an external asset interface. The host resolves logical asset IDs into resources; Tessera must not hard-code filesystem or network access.

The strategy's illustrative `loadUiAsset(id)` is a starting point. Finalize handle ownership, readiness/failure states, cancellation, fallback, resource invalidation, and replacement separately. Low-level image drawing can be tested in the primitive backend phase before the application-facing `Image` asset component lands.

## Verification

Validate draw-list order, balanced stacks, invalid handles, and completion-safe resource lifetime independently of screenshots. Use a few image cases for overlapping rectangles, clipping, transforms, alpha, borders, and later images/glyphs. Record viewport scale, target format, backend, device, and tolerances with results. A shader compile check alone is not runtime rendering evidence.

The CPU reference backend renders the same draw lists as GPU candidates, and comparison is tolerance-aware because floating-point rounding, texture filtering, shader derivatives, and color conversion can differ. Comparison conditions must account for GPU subpixel geometry precision and exact fragment-discard boundaries. Optimized CPU paths are compared with the scalar result, and deterministic mode with repeated runs and different thread counts.

[Vulkan fixtures](../../tests/render/vulkan_tests.cpp) provide a host-owned offscreen target, procedural 2x2 image, queue/fence/readback, required validation layer with synchronization validation, numeric pixel assertions, and PPM artifacts. They exercise source-over order, rounded/inside borders, nested/empty/mirrored clips with pixel-center fractional edges, composed/rotated/skewed transforms, image sampling/crop/tint, scale/resize, rejected calls, capacity and retirement. Placeholder fixtures additionally check bitmap/baseline/multiline/space/missing marks at four scales, glyph clip/transform/alpha, atomic rejection, and a JSON -> tree -> layout -> paint -> GPU Text menu. Both paths run these fixtures; batch checks also compare complete mixed-scene images against the reference at four scales and check draw counts, multiple retained uploads, rejection, and partial/future retirement. They fail when required device/layer capabilities are absent; they do not silently substitute CPU rendering. The [development guide](../guides/development.md#optional-vulkan-workflow) owns execution commands.
