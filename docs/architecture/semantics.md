# Semantics and external adapters

## Core invariants

- Semantic records project one settled runtime generation, separate from paint commands and layout containers.
- Names, state and action availability derive from shared runtime/interaction rules; external adapters do not maintain competing eligibility.
- Semantic invocation uses ordinary action boundaries and rejects stale identities. Presentation relocation or absent paint cannot alone define logical meaning.

## Proposed semantic projection

`SemanticTree` is a backend-neutral projection of the settled UI snapshot, separate from paint commands and geometry. It represents meaning for accessibility, automated tests, external agents, and inspection. This section defines a proposal, not JSON v1 fields or a stable public API; the [implemented prototype](#implemented-prototype-projection) covers a small in-process subset. Actual capability status is in [support](../reference/support-matrix.md).

Each semantic entry needs:

- Identity associated with a live node, plus an explicitly scoped stable author identity for replay/inspection when available.
- Role, accessible label/name, optional value, and relationships.
- Enabled, focused, selected, and other role-specific states.
- Supported logical actions, with targets governed by the [input action boundary](input.md#event-to-action-boundary).
- Ordered semantic children; exact flattening of non-semantic containers is an open decision.

Derive enabled/focused/action availability from settled interaction state rather than maintaining competing state in adapters. Names may use explicit labels or relationships; define missing-reference, cycle, and fallback diagnostics before freezing schema v1. Existing `labelled_by` storage remains governed by [UI model](ui-model.md) and [JSON v1](../../formats/tessera-ui/README.md).

Semantic inclusion for hidden, display-none, virtualized, and modal content needs explicit fixtures. Do not infer eligibility solely from whether a paint command exists.

Portal relocation preserves declared logical component relationships under the [portal model](../proposals/overlays-and-portals.md#proposed-overlays-and-portals); presentation parentage alone cannot determine semantic ownership. Modal scope and background action availability reflect [input](input.md#proposed-overlay-interaction). Virtualized lists declare exposed logical item order, stable keys, and realization actions under [virtualization](../proposals/virtualization.md#proposed-virtualization-foundation), rather than making visible indices into identities. Editable text exposes committed value, selection, read-only state, and declared editing actions from the [editing owner](input.md#proposed-editing-ime-and-clipboard-boundary). Relationship, value/selection, and virtualization encoding require explicit schema decisions before extending semantic snapshots.

## Implemented prototype projection

[semantics.hpp](../../include/tessera/semantics/semantics.hpp) implements an in-process subset of this proposal. It is a prototype, not a stable API. Roles derive from node vocabulary, the optional Box `separator`/`modal`/`scrollbar` markers and the bounded `collection_role` vocabulary; there is no general authored role enumeration.

- **Input.** `SemanticInput` borrows the same coherent tree/resolved-style/layout snapshot as [hit testing](input.md#implemented-rectangular-hit-testing) and is rejected with the same located snapshot codes. An optional `focused` handle carries host focus for that snapshot, such as `FocusDispatchResult::focused`; a handle from another tree fails as `stale_target` at `/focused`. No text shaper or renderer is involved.
- **Inclusion and order.** `build_semantic_tree` scans displayed nodes in tree preorder. Display-none subtrees have no entries. Visibility is local: a hidden node is excluded, while its visible descendants attach to the nearest included ancestor. Roles are `dialog` for a Box with `modal: true`, the bounded collection roles described below, then `separator` for a Box with `separator: true` or `scrollbar` for `scrollbar: true`, otherwise `button` for a Box or Text with an `activate` binding, `text` for a Text node outside a button/separator/scrollbar/item, and `root` for a Box root with none of these. Other Boxes are flattened. Text whose nearest included ancestor is a button, separator, scrollbar or item is presentational: it names that entry and has no entry. A nested control keeps its own entry and label. A hidden root yields top-level entries without a parent.
- **Entries.** `SemanticNode` owns the author ID and records the live `NodeHandle`, parent entry index, `LayoutResult` box index for bounds, role, name and `NameSource`, the `labelled_by` target handle, `enabled` (false when the node or an ordinary/logical tree ancestor is disabled), `focusable` and `focused` state, eligible actions, optional item `selected` and optional tree-branch `expanded` state, and the optional presented `value` of a text or number input. Disabled entries remain exposed without actions. No other role carries a value. Handles expire with their tree; entries are not a serialized identity.
- **Focus state.** `focusable` is [focus dispatch](input.md#implemented-prototype-focus-dispatch) eligibility, computed by the same shared rule: because entries are displayed and visible, an entry is focusable when it is enabled and its `focusable` property is true. `focused` is true only on the focusable entry whose node is the supplied focus. Supplied focus on a disabled, hidden, or display-none node is reported on no entry, as [style resolution](styling.md#implemented-prototype-style-resolution) suppresses `:focus` on disabled nodes; hosts refresh focus dispatch after snapshot changes so that the supplied focus is eligible. Projection never moves or recovers focus. An eligible focused node without an entry, such as a focusable presentational label or a flattened Box, produces a successful result with a `focus_not_exposed` warning at `/nodes/<preorder index>`, and no entry reports focus.
- **Names.** A `labelled_by` reference names the entry with the Text content of the referenced subtree in preorder, including hidden or display-none content. References are not followed transitively, so relationship cycles cannot recurse. An empty relationship result falls back to content: a button's visible presentational Text runs, or a Text entry's own text. Nonempty runs are joined by one space without other whitespace normalization. Document validation already rejects missing references. A button without a name produces a successful result with a `missing_name` warning at `/nodes/<preorder index>`.
- **Invocation.** `request_semantic_action(input, target, binding)` re-projects the supplied snapshot and returns the ordinary `ActionRequest` for that binding owner. A handle from another or destroyed tree fails as `stale_target` at `/target`, even when the replacement reuses author IDs. Display-none or hidden targets are `hidden_target` and disabled entries are `disabled_target`, both at `/target`. Only exposed `activate` and applicable tree-branch `expand`/`collapse` bindings are supported; labels, flattened containers and other bindings are `unsupported_action` at `/binding`. No host callback runs and no state changes.

Prototype [inspection](inspection.md#implemented-prototype-capture-and-target-resolution) resolves role/name targets against this projection and invokes them here. [Replay](replay.md#implemented-prototype-playback) records owned copies of this projection per generation and focus-changing step, and plays semantic action steps through the same invocation. The owned schema and generation-aware invocation below use this projection; broader selection/value state and platform/DOM adapters follow the proposals in this page.

Collections project `list`, `tree`, `list_item` and `tree_item` roles before ordinary button/separator derivation. Item text is presentational; explicit label references exclude disclosure/selection markers from names. `selected` is independent of focus and is present for authored items; `expanded` is present only for branches, not leaves. A branch exposes activation plus only the expansion binding matching its controlled state. `tree_parent` supplies logical semantic parentage for flat layout rows; an excluded logical parent is skipped toward the nearest included logical ancestor, otherwise the collection. Disabled logical ancestry shares input/style eligibility. Authoring explicitly hides collapsed descendants; projection never changes expansion or selection. The [collection guide](../guides/tree-list.md) owns composition and scope.

The [Modal](input.md#implemented-modal-interaction) marker takes role precedence as `dialog`; its ordinary `labelled_by` names the dialog, and unnamed dialogs warn as `missing_name`. Child text/buttons keep ordinary entries under it. The layer exposes no activate action. While a Modal is active, shared input eligibility projects background entries as disabled/nonfocusable without actions; semantic invocation rejects them as `disabled_target`. This does not claim a native accessibility adapter. The additive `dialog` role round trips in Semantic JSON v1 and Replay v1/v2 role/name targets; older readers reject it, while existing role spellings remain unchanged. [Owner checks](../../tests/input/modal_tests.cpp) cover title naming, scope exclusion and serialization.

[Menus](../guides/menu-context.md) project additive `menu`/`menu_item` roles from `collection_role`. Explicit label references name menus and command rows; item text is presentational. Enabled items expose one ordinary activate action and no selected/expanded state; disabled or modal-blocked items expose none. Closed/suppressed menus have no entries. Menu roles round trip in Semantic JSON v1 and Replay v1/v2 targets and are accepted by inspection/invariants. Existing spellings remain unchanged; older readers reject the additions. This does not introduce a native accessibility adapter or inferred has-popup/expanded relationship on the trigger.

[RadioGroup](../guides/radio-group.md) projects additive `radio_group`/`radio` roles from `collection_role`. The group is named by its title and exposes no action. Each radio is named by its label reference, carries `selected` as its checked state and, while enabled, one ordinary activate action; the marker is presentational. Both roles round trip in Semantic JSON v1 and Replay v1/v2 targets and are accepted by inspection/invariants; older readers reject them. No mixed state or native accessibility adapter is introduced.

[Tabs and Toolbar](../guides/tabs-toolbar.md) project additive `tab_list`, `tab` and `toolbar` roles from `collection_role`. Tab lists and toolbars are named by their display-none titles and expose no action. Each tab is named by its label reference, carries `selected` and, while enabled, one ordinary activate action. Toolbar controls keep their own roles under the toolbar entry, and tab panel content keeps its ordinary semantics; no tab panel role or controls relationship is introduced. The roles round trip in Semantic JSON v1 and Replay v1/v2 targets and are accepted by inspection/invariants; older readers reject them.

[Checkbox and Switch](../guides/checkbox-switch.md) project additive `checkbox`/`switch` roles from the Box-only `toggle_role`. Each is named by its label reference and carries `selected` as its checked/on state and, while enabled, one ordinary activate action; marker, track and thumb are presentational. Both roles round trip in Semantic JSON v1 and Replay v1/v2 targets and are accepted by inspection/invariants; older readers reject them. No mixed state or native accessibility adapter is introduced.

[TextInput and NumberInput](../guides/text-number-input.md) project additive `text_input`/`number_input` roles from the Box-only `edit_role`. Each is named by its label reference and carries `value`, the presented text taken from the paired Box-only `edit_value` (the draft text for a number input, not a parsed number), and while enabled one ordinary activate action. Label, value, selection and step Text are presentational. Both roles and `value` round trip in Semantic JSON v1 and Replay v1/v2 and are accepted by inspection/invariants; older readers reject them. Selection, caret geometry, numeric range and increment/decrement actions are not exposed, and no native editable-text adapter is introduced.

[VerticalScrollbar](../guides/scrollbar.md) projects the additive `scrollbar` role from its Box-only boolean marker, which cannot combine with another role marker. Thumb text is presentational and its hidden `labelled_by` names the current/maximum logical offset. Enabled thumbs expose ordinary focus and one activate action; disabled/zero-travel thumbs expose no actions, and no-overflow thumbs are display-none. The role round trips in Semantic JSON v1 and Replay v1/v2 and is accepted by inspection/invariants. Numeric range/orientation fields, increment/decrement actions and native accessibility remain unimplemented; older readers reject the addition.

## Implemented semantic snapshot contract

[semantic_snapshot.hpp](../../include/tessera/semantics/semantic_snapshot.hpp) defines owned `SemanticSnapshot` and `SemanticRecord` values, `capture_semantics`, `load_semantics`, and `save_semantics`. The semantic schema version is independent of UI-document and replay versions. `capture_semantics(input, generation)` uses the projection above and preserves its warnings. Replay observations use the same `SemanticRecord` through `ReplaySemanticNode`; they do not define a second semantic schema.

The host supplies a logical update sequence, separate from process-specific tree identity, and advances it after every settled change. A node identity is `(generation, authored preorder index)`, scoped to that host session/document. The overload `request_semantic_action(input, current_generation, SemanticIdentity, binding)` rejects a different generation or an out-of-bounds node as `stale_target` at `/target`, then enters ordinary semantic eligibility. A reload that reuses author IDs cannot authorize an old identity when the host advances its sequence. Hosts own sequence-to-live-tree mapping; a loaded snapshot is an observation and grants no invocation authority.

Semantic JSON v1 requires the original fields, permits optional collection state fields, rejects unknown/duplicate members and coercion, and uses null for absent optional identities/state:

| Object | Fields |
| --- | --- |
| Snapshot | `version`: 1; `generation`: canonical unsigned 64-bit decimal **string**; `node_count`: total authored nodes, including flattened/hidden/display-none nodes; `nodes`: ordered semantic entries |
| Entry | `node`: authored preorder index; `id`: author ID or null; `parent`: semantic entry index or null; `role`: `root`, `button`, `text`, `separator`, `dialog`, `list`, `tree`, `list_item`, `tree_item`, `menu`, `menu_item`, `scrollbar`, `radio_group`, `radio`, `checkbox`, `switch`, `text_input`, `number_input`, `tab_list`, `tab`, or `toolbar`; `name`: UTF-8 string; `name_source`: `none`, `relationship`, or `content`; `labelled_by`: authored preorder index or null; `enabled`, `focusable`, `focused`: booleans; `actions`: eligible action array; optional `selected` and `expanded`: boolean or null; optional `value`: UTF-8 string |
| Action | `binding`: `activate` or the applicable tree `expand`/`collapse`; `action`: host action name |

No handles, tree identities, pointers, or platform types are encoded. Geometry is joined by authored node index from the same generation under [inspection](inspection.md), rather than duplicating layout fields. Collection state is additive: canonical output omits absent state fields, preserving legacy record bytes. Selection belongs only to list/tree items, radios, tabs and toggles, expansion only to tree items, and `value` exactly to text and number inputs. Older readers reject new roles/state/actions rather than silently treating them as buttons. No other role carries a value. Relationship references can name nodes with no semantic entry and never request transitive name resolution.

Validation bounds the authored count to 1–10000 and entries to that count, requires strictly increasing authored indices, unique author IDs, and preceding parents with contiguous semantic subtrees. References stay within the authored count. A `root` role names only the authored root. Names have source `none` exactly when empty; a relationship-derived name requires a reference. Disabled entries cannot be focusable or expose actions; focus requires focusability and at most one focused entry. Actions belong only to enabled buttons, separators, scrollbars, items, radios, tabs, toggles or inputs, contain at most one `activate` plus one applicable tree expansion action without duplicate bindings, and use nonempty UTF-8 host names without ASCII controls. Empty forests are valid, for example for entirely invisible content.

SplitPane's separator name includes the host-controlled logical size and its activate binding requests the ordinary adjustment command. Numeric value/range/orientation fields, separate increment/decrement actions and native accessibility adapters remain unimplemented. `separator` is an additive role in semantic JSON v1 and replay role/name targets; previous builds reject the new role rather than silently treating it as a button. Existing root/button/text records keep their encoding and behavior. [SplitPane checks](../../tests/input/split_pane_tests.cpp) cover marker and semantic round trips, replay role resolution/invocation, disabled eligibility and generation rejection.

Canonical output sorts object keys, preserves array order, writes absent identities as null, and ends in one LF. Encoding the host sequence as a decimal string preserves every 64-bit value without binary64 rounding; leading zeroes, signs, and overflow fail as `schema_type` at `/generation`. Input/output is bounded to `max_serialized_semantic_bytes` (16 MiB), parsed values to 300000, and nesting to the shared parser's 256 levels. Unsupported versions are `unsupported_version`; field/parser errors retain their ordinary codes. Structural failures use located `invalid_identity`, `invalid_parent`, `invalid_reference`, `invalid_role`, `invalid_name`, `invalid_state`, and `invalid_action` diagnostics, alongside UTF-8/identifier/duplicate-ID checks. Load failures include JSON pointers and UTF-8 byte offsets; failure returns no partial value. Capture owns its values after the live tree expires; saving can reject a captured value that exceeds serialization bounds.

[Snapshot checks](../../tests/semantics/semantic_snapshot_tests.cpp) cover projection/round-trip agreement, hidden label references, canonical full-width generations, disabled/focus/action consistency, malformed identities and parent order, input bounds, and generation-aware invocation through ordinary eligibility.

## Snapshot and identity

Publish a coherent semantic snapshot with the same update generation as style/layout and actions under the [frame lifecycle](overview.md#frame-scheduling). Borrowed runtime handles expire with their tree. External adapters need a generation-aware identity and must reject stale action targets after replacement. Do not serialize process-unique handles into recordings.

Semantic output is deterministic for the same document, state, input, time, and resource readiness. Geometry may be supplied for adapter needs through layout references; semantics does not own layout calculation.

## Accessibility and automation boundary

Platform adapters translate this projection to native services such as Windows UI Automation or macOS accessibility. The [Web host](../proposals/web-host.md#proposed-semantic-dom-bridge) projects it to semantic DOM alongside canvas rendering. OS/DOM types stay outside core, and all adapters share the same semantic schema.

An external automation adapter may find a role/name, inspect state, and invoke a declared semantic action. Invocation passes through the same eligibility, host action, and [command](commands.md) path as normal interaction, and a node bound to a disabled command reports itself disabled; adapters do not call component callbacks or host functions directly. A semantic schema does not imply native screen-reader integration, a bundled AI runtime, or supported automation transport.

Path-finder and external tools consume this projection through [shared inspection](inspection.md), alongside [reflection](../proposals/property-reflection.md#proposed-property-reflection), without defining a second semantic schema. Inspection owns target resolution and source/geometry joins; it does not redefine accessible names or actions. Adapter transport, authorization policy, and platform-specific lifetime mapping are integration decisions.

## Verification

Check deterministic order, roles/names/relationships, state consistency, supported-action eligibility, hidden/modal content, and stale identity rejection. [Semantic checks](../../tests/semantics/semantics_tests.cpp) verify prototype roles, flattening, hidden/display-none inclusion, relationship/content names with fallback and warnings, disabled state, repeated-projection equality, pointer-equivalent invocation with located rejections, and agreement of `focusable`/`focused` with focus dispatch and a resolved `:focus` rule. Modal content, native accessibility, and external automation each require their own fixtures or adapter evidence. Use semantic and expected-action fixtures with [Replay](replay.md); results are recorded only in support.
