## v0.3.0 — Dynamic UI and editor prototype

Objective: prove a real dynamic application and editor workflow through one Tessera runtime. The integration target is a small [Path-finder/editor prototype](../design/path-finder-integration.md#proposed-mini-prototype) built from ordinary Tessera components, with preserved state, live reload, a generic Inspector, overlays, text editing, deterministic capture, and validation.

Depends on menu/text/style foundations and explicit document identity/versioning.

Start from an inventory/tool panel driven by host-owned selection and item data, then connect it to the mini editor. Prioritize the end-to-end loop of author, reload, inspect, operate, capture, and verify. Add a subsystem only when it closes that loop or the prototype requires it; preserve full-tree style/layout/semantic/paint evaluation as the correctness reference.

### Remaining work in priority order

Define invocation-scoped async declarations and declaration-driven detachment over [owner-bound async cleanup](../design/ui-model.md#implemented-owner-bound-async-detachment), [declared component cleanup](../design/ui-model.md#implemented-declared-component-cleanup) and [declared effects](../design/ui-model.md#implemented-declared-component-effects), declaration origins, and [UI error fallback](../design/ui-model.md#proposed-error-boundaries). Add [resource payloads](../design/ui-model.md#proposed-async-state), image assets for thumbnails, and completion-safe retirement as required by the fixture.
2. **Atomic live reload and compatible state.** Implement the [reload transaction](../design/path-finder-integration.md#live-reload-transaction) over ordinary generation publication, with declared compatibility/migration and subtree recreation. Extend [source provenance](../design/inspection.md#proposed-inspection-records-and-source-mapping) with declaration/default origins and typed diagnostic context; link accepted edits to preview and verified snapshots.
3. **Full reflection and schema-driven Inspector.** Join [property schema and generation observations](../design/ui-model.md#proposed-property-reflection); generate property editors from metadata, validate edits, and enter ordinary runtime/command/transaction paths. Keep affected-stage metadata for later incremental evaluation.
4. **OverlayRoot and Portal.** Define shared [ownership](../design/ui-model.md#proposed-overlays-and-portals), [placement](../design/layout.md#scrolling-and-overlay-geometry), [focus scopes and targeting](../design/input.md#proposed-overlay-interaction), and [semantic relationships](../design/semantics.md#proposed-semantic-projection). Compose bounded Tooltip/Dropdown/Modal primitives. Integrate gesture completion/cancellation with native capture/lifecycle adapters and reactive owner disposal; validate native pointer/render transform agreement where the prototype uses transforms.
5. **TextInput.** Build the minimum [string property editor](../design/input.md#proposed-editing-ime-and-clipboard-boundary): Unicode text, caret/selection, insertion/deletion, left/right/home/end, host clipboard adapter, backend-neutral composition contract, and [logical replay](../design/replay.md#proposed-editor-workflow-inputs). Multiline is optional when inexpensive; a rich-text editor is excluded.
6. **VirtualList.** Prove [bounded realization and deterministic measurement](../design/layout.md#proposed-virtualization-foundation) over stable item keys, keyed state, focus, scroll anchors, async rows, and an explicit semantic virtualization policy. Use it for an editor panel.
7. **Snapshot bundle and CLI.** Implement a small [inspection/render consumer and versioned machine-readable bundle](../design/inspection.md#proposed-runner-and-snapshot-bundle), with semantic/layout/invariant/counter and selective visual comparisons. Default deterministic captures to the CPU reference backend and compare Vulkan against the same scene under declared tolerances. Integrate runner/reload invariants and source-edit-to-verification instrumentation.
8. **Path-finder mini prototype.** Connect toolbar, hierarchy/list, central preview, Inspector, [command palette](../design/commands.md#proposed-command-palette), dropdown/modal/tooltip, text editing, async resource, reload, and undoable gesture through ordinary components. Extend keyboard/gamepad shortcut host integration with platform key/device-button conventions; all input routes share command eligibility and generation checks.
9. **Agent capability manifest v0.** Expose [machine-readable operation discovery](../design/inspection.md#proposed-agent-capability-manifest) for the prototype's ordinary inspect, invoke, replay, capture, invariant, source-edit, reload, and comparison boundaries. Build the manifest alongside verification so integration can exercise the full agent loop.
10. **Measure before optimizing.** Profile real prototype workloads and record authoring friction to choose v0.4.0 scope. Aggressive incremental evaluation and GPU optimization follow this proof; they are not completion prerequisites.

The dependency sequence groups runtime lifecycle first, then reload/reflection, overlays and native gesture integration, editing/list/palette, verification/manifest, and final integration/profiling. Build the prototype progressively as a consumer of each boundary; the ordered list is not a requirement to postpone integration until every subsystem is isolated and finished.

### Exit criteria

- **Dynamic UI:** components automatically own registered view state; keyed reorder preserves identity, focus, bindings, and state. Disposal is deterministic, stale async results cannot update recreated lifetimes, and component failures produce a declared contained fallback. Missing/replaced assets and theme variables obey fallback/diagnostic rules and resources retire safely.
- **Coherent publication:** graph/batch/lifetime regression fixtures preserve settlement, equality suppression, located failure recovery, and no evaluations/effects after disposal. One successful event batch publishes at most one visible generation, and explicit reads deliver no partial effects.
- **Editing:** source label/style/layout edits reload atomically and preserve declared compatible owners, state, focus, scroll, selection, and resources. Incompatible subtrees recreate safely; invalid edits keep the previous valid UI with declaration/expression diagnostics. Runtime and preview round-trip the same document and editor metadata.
- **Inspector:** a generic UI discovers property editors from runtime metadata without hardcoded Box/Text property tables. Candidate edits validate, use ordinary runtime/command/transaction boundaries, publish one generation, and expose changed property/source observations.
- **Application UI:** Tooltip/Dropdown/Modal share Portal ownership, geometry, hit rules, semantic relationships, command scopes, and keyboard/gamepad focus recovery. TextInput edits ordinary string properties; a VirtualList editor panel displays a bounded set from thousands of keyed logical items with deterministic state, focus, scroll, async, replay, and inspection behavior.
- **Commands and history:** menu, keyboard/gamepad shortcut, palette, pointer, semantic, and replay requests share eligibility. Continuous gestures span batches with one host-owned transaction/history entry; cancellation rolls back once and non-editing actions create no edit token.
- **Verification:** a headless fixture loads, replays, and captures reproducible CPU-reference observations/images. Both Vulkan paths agree with the same scene within declared tolerances. Replay, semantics, inspection, source map, invariants, and completed capture identify one coherent generation; bundles emit machine-readable observations/differences and diagnose invalid versions or incompatible conditions.
- **Integration:** the mini editor itself uses Tessera components and the same runtime for application execution and preview. An agent can inspect, operate, edit/reload, capture, evaluate invariants, and compare it through declared ordinary boundaries. Representative profiling and recorded friction inform the next milestone.

### Deferred scope

Keep [backlog](backlog.md) ownership for aggressive incremental rendering, retained GPU caches, deep GPU optimization, WebGPU/browser hosts, Python/application bindings, broader layout, and a large animation system. Add only layout/animation behavior that the prototype concretely requires. Preserve backend neutrality, affected-stage metadata, deterministic clock/replay boundaries, and full-tree correctness while selecting subsequent work from measured requirements.
